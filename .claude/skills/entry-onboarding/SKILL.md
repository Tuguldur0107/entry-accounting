# Анхны нэвтрүүлэлт — Entry Accounting

Эх дүрэм: `docs/deployment/onboarding.md` (product owner баталсан, v1.0).
MCP-ээр `get_onboarding_guide` tool ЯГ ТЭР баримтыг өгдөг — эхлээд түүнийг
дууд, дараа нь энэ skill-ийн дарааллаар ажилла. Техник импортын дараалал
`master-data-import` skill-д.

## Эхлэхэд (ЗААВАЛ)

1. `get_onboarding_guide` (overview) — байгууллагын ШАТ (0–5), дараагийн
   алхам, AI-ийн хязгаарыг унш. Шат 0 биш бол өмнөх ажлыг давхардуулахгүй.
2. `get_onboarding_guide section=checklist` — 13 материалын жагсаалт.
3. `get_onboarding_guide section=rules` — R0–R9. Зөрүү бүрд ЭДГЭЭР дүрмээс
   гадуур арга ХЭРЭГЛЭХГҮЙ.

## Шат 0 — Судалгаа (юу ч бичихгүй)

- Хэрэглэгчийн хавтсыг бүхэлд нь унш (Excel/CSV/PDF). Файл бүрийг
  шалгах жагсаалтын 13 мөрийн алинд тохирохыг тогтоо.
- **Gap тайлан** хүснэгтээр: материал · байгаа/дутуу · файл · орлуулах арга
  (R1–R5) · нөлөө (жишээ: "aging тайлан хураангуй дээр буруу гарна").
- Cut-off огноо (нэвтрүүлэлтийн өмнөх өдөр), хуучин системийн TB тэнцэж
  байгаа эсэхийг (R0) ил хэл.
- Дансны mapping (R1): `list_gl_accounts` → хуучин данс бүрийг стандарт
  дансанд харгалзуулсан хүснэгт, итгэлийн түвшинтэй. Батлуулаад
  `00-account-mapping.csv` болгож хэрэглэгчид өг.
- Хэрэглэгч gap тайлан + mapping-ийг БАТЛАХААС өмнө MCP-ийн бичих tool
  ДУУДАХГҮЙ.

## Шат 1 — Master data

`master-data-import` skill-ийн дараалал (данс → харилцагч → бараа/агуулах →
касс → ажилтан → ҮХ). Нэмэлт:

- Нээлтийн зөрүүний данс (`44000098 Нээлтийн үлдэгдлийн зөрүү`) байгаа
  эсэхийг `get_onboarding_guide section=status`-аас шалга; байхгүй бол
  хэрэглэгчид /settings/gl → "Стандарт данс sync" эсвэл `create_gl_account`.
- R2 хэрэглэх бол хураангуй харилцагч `Нээлтийн үлдэгдэл — задаргаагүй (АР)`
  / `(АП)`-г `create_counterparty`-оор нэг удаа үүсгэ.

## Шат 2 — Нээлтийн үлдэгдэл

1. Дэд дэвтэр эхлээд: АР/АП (`create_arap_invoices_batch`, externalRef =
   хуучин дугаар), бараа (`create_inventory_movement` орлого өртөгтэй), ҮХ
   (`create_fixed_assets_batch`), касс `openingBalance`.
2. Задаргаагүй бол хураангуй: R2 (`externalRef: opening-summary:ar|ap`,
   тайлбар `[ОНБ-ХУРААНГУЙ] …`), R3/R5 — зөвхөн GL-д нийт дүнгээр.
3. Нээлтийн журнал НЭГ ноорог: `create_journal_voucher`, огноо = cut-off,
   `externalRef: opening-balance:<cut-off>`. Дэд дэвтэрт орсон дансны мөрийг
   ОРУУЛАХГҮЙ (R8 — давхар тоолохгүй).
4. `post_*` ДУУДАХГҮЙ — нягтлан вэб дээрээс батална (R9).

## Шат 3 — Тулгалт

1. `get_trial_balance` (cut-off) — хуучин TB-тэй мөр мөрөөр хүснэгтээр тулга.
2. `reconcile_modules` (to = cut-off).
3. Зөрүү бүрд шалтгаан хай (mapping алдаа, давхар тоолсон, дутуу файл).
   Тайлбарлагдахгүй бол R6: `create_journal_voucher`
   `externalRef: opening-diff:<cut-off>:<n>`, тайлбар `[ОНБ-ЗӨРҮҮ] <данс> ·
   <дүн> · шалтгаан: …`, зөрүүний данс руу, НООРОГ.
4. Зөрүүний тайланг хэрэглэгчид: данс · дүн · магадлалт шалтгаан · хэн шийдэх.

## Шат 4–5 — Зэрэгцээ сар, хүлээлгэн өгөх

- Эхний сарын гүйлгээ `get_workflow_guide`-ийн урсгалуудаар;
  `get_month_end_checklist`.
- Задаргаа хожим ирвэл R7: залруулга ШИНЭ журналаар (`opening-adj:<огноо>:<n>`,
  `[ОНБ-ЗАЛРУУЛГА] …`), хураангуйг эсрэг талаар хааж дэлгэрэнгүйг дэд дэвтрээр.
- `opening-diff:*` ноорог 0 болтол cut-off сарыг хаахгүй (OD-ONB-4).
  Хаагдсан сард залруулга хэрэгтэй бол default: сарыг дахин нээж cut-off-оор;
  хэрэглэгч татгалзвал дараагийн сарын 1 (OD-ONB-3).

## Хатуу дүрэм (давтан)

- Дүн, ханш, үнэ зохиохгүй. Зөрүүг хуримтлагдсан ашиг/түр дансанд хаахгүй.
- Бүх нээлт/зөрүү/залруулга НООРОГ — Шууд бичих горимд ч.
- Batch 100 мөр; алдаатай мөрийг жагсаалтаар буцаана; `[CONFLICT]` = давхардал.
- Файл бүрийг урьдчилан харуулж батлуулна; батлаагүй бол юу ч бичихгүй.
- Дуусахад тайлан: шат · оруулсан/алгассан/алдаатай · хураангуй бүртгэлүүд ·
  зөрүүний ноорогууд · дараагийн алхам.
