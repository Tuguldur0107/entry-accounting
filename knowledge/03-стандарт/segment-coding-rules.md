# Сегментийн код — ЗААВАЛ МӨРДӨХ ДҮРЭМ

> Энэ нь Entry системийн **хатуу дүрэм**. Журнал, тайлан, модуль (Cash, AR, AP,
> FA, Payroll …) бичих бүх хөгжүүлэлт энэ дүрмийг **зөрчихгүй** дагана.
> Холбогдох spec: [`segment-strategy.md`](segment-strategy.md) §7.
> Реализаци: **`lib/segments.ts`** (single source of truth).

## 1. Сегментийн бүтэц

GL дансны код = **10 сегментийн composite**, "." -аар холбосон:

```
S1 . S2 . S3 . S4 . S5 . S6 . S7 . S8 . S9 . S10
```

| Сегмент | Нэр | Орон | Default (тэг) |
|---------|-----|:----:|---------------|
| S1 | Компани | 3 | `000` |
| S2 | Зардлын төв | 6 | `000000` |
| S3 | **Үндсэн данс** (CoA) | 8 | `00000000` |
| S4 | Бүтээгдэхүүн | 2 | `00` |
| S5 | Төсөл | 4 | `0000` |
| S6 | Группын дотоод | 3 | `000` |
| S7 | Холбоотой этгээд | 4 | `0000` |
| S8 | Мөнгөн гүйлгээ (IAS 7) | 4 | `0000` |
| S9 | **Модуль** | 2 | `GL` (тэг БИШ) |
| S10 | Нөөц | 1 | `0` |

## 2. ДҮРЭМ 1 — Хадгалах код (DB)

1. Хадгалах код **ҮРГЭЛЖ бүтэн 10 хэсэгтэй** байна.
2. **Идэвхтэй + утгатай** сегмент → хэрэглэгчийн оруулсан утга.
3. **Идэвхтэй ч хоосон үлдсэн** сегмент → орон тоогоор нь **ТЭГ** (default).
4. **Идэвхгүй (унтарсан)** сегмент → орон тоогоор нь **ТЭГ** (default).
5. Цорын ганц онцгол: **S9 (Модуль)** хэзээ ч тэг биш — модулийн код (`GL`, `AR`, `AP`…).

> ❌ Буруу: `..51100000...000.0000..GL.0` (хоосон хэсэгтэй)
> ✅ Зөв:  `000.000000.51100000.00.0000.000.0000.0000.GL.0`

**Шалтгаан**: хоосон тэмдэгт (`""`) ба тэг (`0000`) хоёр өөр утга болж, validation
(`segment8 != '0000'`), тайлангийн group, нэгтгэлийг эвддэг.

## 3. ДҮРЭМ 2 — Унтарсан сегмент = харагдахгүй, гэхдээ хадгалагдана

- Сегмент унтарсан бол UI-д **харагдахгүй** (picker, багана, дэлгэц).
- Гэхдээ DB-д тухайн сегмент **тэг default-аар хадгалагдана** (ДҮРЭМ 1).
- Идэвхтэй сегментийн жагсаалтыг **`computeActiveSegIds()`** өгнө: S3 ҮРГЭЛЖ
  идэвхтэй; бусад нь тодорхой унтраагаагүй бол идэвхтэй (тохиргоо байхгүй → идэвхтэй).

## 4. ДҮРЭМ 3 — Тайлангийн нэгтгэл (aggregation)

- Тайлан **тодорхой сегментийг ашиглаагүй бол** → тэр сегментийн **бүх утгыг
  НИЙЛБЭРЛЭНЭ** (тухайн сегментээр group хийхгүй).
- Жишээ: GL trial balance зөвхөн S3-аар зүснэ → S1/S2/S4…S10-ийн бүх утга нэг
  S3 дансны мөрөнд нийлбэрлэгдэнэ.
- Сегмент тус бүрийн "зүсэлт" ([`segment-strategy.md` §7.8](segment-strategy.md)):
  Cost = S2+S3+S4, Cashflow = S8, Project = S5, Consolidation = S1+S3+S6 г.м.
- Үндсэн данс гаргахад **`extractMainAccount(code)`** ашиглана (composite/plain/legacy бүгдэд ажиллана).

## 5. Хэрэгжүүлэлтийн гэрээ (implementation contract)

Бүх код **`lib/segments.ts`**-ийн функцуудыг ашиглана. Хуваагдсан/давхардсан
логик (өөрийн `SEG_DEFAULTS`, гар `split(".")` parse) бичихийг **хориглоно**.

| Хэрэгцээ | Функц |
|----------|-------|
| Код угсрах | `buildSegmentCode(activeParts, activeSegIds, extraDefaults)` |
| Код задлах | `parseSegmentCode(code, activeSegIds)` |
| Үндсэн данс (S3) гаргах | `extractMainAccount(code)` |
| Дэлгэцэнд харуулах | `formatSegmentDisplay(code, activeSegIds)` |
| Идэвхтэй сегментүүд | `computeActiveSegIds(segmentConfigs)` |
| Default (тэг) утга | `defaultSegmentValue(id)` |
| Тэг эсэх шалгах | `isZeroSegment(value)` |

## 6. Validation

- Мөрд дүн байгаа бол **S3 (үндсэн данс) тэг байж болохгүй** (`isValidLine` —
  `lib/actions/gl.ts`). Тэг S3 (00000000) руу бичихийг хориглоно.
- §7.6.7: S3 нь касс/банк (10/11) бол **S8 != '0000'** (cash flow заавал).
- §7.6.6: S6 != S1 (компани өөртөө intercompany байж болохгүй).
