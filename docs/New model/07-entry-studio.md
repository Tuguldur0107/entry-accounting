# Даалгавар: Entry Studio — систем доторх vibe coding-ийн архитектурын төлөвлөгөө

**ЭХЛЭЭД** `PLAN.md`, `PLAN-extension-sdk.md`, `PLAN-tiers.md`-г унш.

Зорилго: **КОДЫН МЭДЛЭГГҮЙ** хэрэглэгч entry дотор монголоор бичээд өөрийн бизнесийн автоматжуулалт, тайлан, импортыг үүсгэж чаддаг болгох. Хэрэглэгч repo, API key, deploy, сервер гэдгийг огт мэдэхгүй байх ёстой.

**Урсгал:** хэрэглэгч монголоор хүсэлт бичнэ → AI extension үүсгэнэ → sandbox дээр dry-run хийж үр дүнг ХҮН ОЙЛГОХ хэлбэрээр харуулна (жишээ нь "5 харилцагчид ийм имэйл очно", "12 мөр журнал ноорог үүснэ") → хэрэглэгч зөвшөөрнө → extension entry-ийн серверт тусгаарлагдсан орчинд ажиллана → буруу бол нэг товчоор унтраана, хийсэн бичилтийг буцаана.

**Ажлын горим:** судалж `PLAN-studio.md` бичнэ. Код засахгүй. Тусдаа branch.

## 1. Судалгаа

а) Backend-ийн одоогийн deploy орчин (Railway), процесс ажиллуулах боломж, resource хязгаар.

б) Scheduled job / cron одоо байгаа эсэх (extension-ийн ихэнх нь хуваарьт ажиллана).

в) Sandbox tenant үүсгэх боломж (`PLAN-extension-sdk.md`-ээс).

г) AI дуудах давхарга байгаа эсэх — entry өөрөө LLM API дуудаж байна уу, ямар model, ямар өртөгтэй?

## 2. Санал

1. **Runtime**: extension-ийг ямар орчинд ажиллуулах вэ — Deno/V8 isolate, WASM, эсвэл тусдаа container. Гурвыг харьцуулж, Railway дээр хамгийн бодитойг сонго. Хязгаар: CPU, санах ой, ажиллах хугацаа, сүлжээ зөвхөн зөвшөөрсөн домайн, файлын систем хаалттай.

2. **Эрхийн загвар**: extension бүрд scope (`PLAN-tiers.md`-ийн scope-уудыг ашигла). **Default = унших + ноорог үүсгэх.** Батлах, устгах, үе хаах, имэйл илгээх, гадагш сүлжээ хандах эрхийг хэрэглэгч нэг бүрчлэн зөвшөөрнө. Цөмийн дүрмийг extension тойрч чадахгүй гэдгийг баталгаажуул.

3. **Dry-run систем**: extension-ийг sandbox tenant дээр ажиллуулж, үр дүнг ялгаа (diff) хэлбэрээр харуулах. Хэрэглэгч кодыг биш үр дүнг харна. Код харах нь нэмэлт сонголт.

4. **Хувилбар ба буцаалт**: extension бүрийн хувилбар, аудитын мөр (хэзээ хэн юу ажиллуулсан, ямар баримт үүссэн), нэг товчоор унтраах, тухайн extension-ий үүсгэсэн бичилтийг бөөнөөр буцаах.

5. **Хуваарь ба гох**: cron, event (`document.posted` гэх мэт), гараар ажиллуулах гурван горим.

6. **Template сан**: бэлэн extension-үүд (Excel импорт, авлагын сануулга, тайлан экспорт, ebarimt баримт бөөнөөр) — хэрэглэгч нэг товчоор суулгаад тохируулна. Хожим хэрэглэгчид өөрсдийн extension-ээ хуваалцах marketplace-ийн суурь.

7. **AI зардал**: extension үүсгэх бүрд LLM дуудлага гарна. Өртгийн загвар санал болго (түвшин тус бүрийн сарын хязгаар, эсвэл кредит).

8. **Алдааны бодлого**: extension unhandled error өгвөл юу болох, хэдэн удаа дахин оролдох, хэрэглэгчид хэрхэн мэдэгдэх, дараалсан алдаанд автоматаар унтраах.

9. **UI урсгал**: extension үүсгэх, туршилт харах, зөвшөөрөх, жагсаалт, лог харах дэлгэцүүдийн wireframe тайлбар.

## 3. Хязгаарлалт

- Extension хэзээ ч DB-д шууд хандахгүй, зөвхөн scope-той API-аар.
- Batch хэмжээний хязгаар (жишээ нь нэг ажиллалтад 1000 мөрөөс хэтрэхгүй), түүнээс дээш бол хүний зөвшөөрөл.
- Хэрэглэгчийн өгөгдөл LLM рүү явах эсэхийг хэрэглэгчид тодорхой мэдэгдэх, нууцлалын бодлого санал болго.
- Гаднаас SDK-аар бичих хөгжүүлэгчийн зам хэвээр байна, гэхдээ хоёрдогч.

## 4. Гаралт

`PLAN-studio.md`: runtime-ийн харьцуулалт ба сонголтын үндэслэл, эрхийн загвар, dry-run механизм, өгөгдлийн схем, UI урсгал, **3 жишээ extension-ийн бүрэн урсгал** (хэрэглэгчийн хүсэлтээс ажиллах хүртэл), эрсдэл, хэрэгжүүлэх үе шатууд. Монголоор.
