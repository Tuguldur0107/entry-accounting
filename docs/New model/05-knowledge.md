# Даалгавар: "Entry AI skill" — Монголын нягтлан бодох бүртгэл, татварын мэдлэгийн сан

Зорилго: entry хэрэглэгч өөрийн Claude/ChatGPT-ээс "ийм зүйл боллоо, яаж бүртгэх вэ", "энэ татварт хамаарах уу", "хуулийн хүрээнд татвараа яаж бага төлөх вэ", "энэ зөв бүртгэл мөн үү" гэж асуухад Монголын мэргэшсэн нягтлан бодогч шиг хариулж, төгсгөлд нь entry дээр яг яаж хийхийг заадаг мэдлэгийн сан бүтээх.

Энэ бол кодын ажил биш, агуулгын ажил. Гэхдээ агуулга нь entry-ийн MCP resources, `get_workflow_guide`, `get_ui_guide`-тай (`PLAN-ai-layer.md`, `PLAN-ui-guide.md`-г унш) уялдана.

## ЭХ СУРВАЛЖИЙН ДҮРЭМ (хамгийн чухал)

- Хуулийн тоон утга (хувь, хязгаар, шатлал, хугацаа), заалтын дугаарыг ЗӨВХӨН `docs/knowledge-sources/` дахь файлууд эсвэл legalinfo.mn, mta.mn-ээс web-ээр шалгасан эх сурвалжаас ав. **Санах ойгоос бүү бич.**
- Шалгаж чадаагүй утга бүрийг «[ШАЛГАХ: ...]» гэж тэмдэглэ. Би нягтлантайгаа хамт баталгаажуулна.
- Мэдлэг бүрт: эх сурвалж, хүчинтэй огноо (valid_from), сүүлд хянасан огноо гэсэн frontmatter байна.
- "Татвар бага төлөх" сэдэв ЗӨВХӨН хууль ёсны хүрээнд: хөнгөлөлт, чөлөөлөлт, зөв ангилал, хугацааны төлөвлөлт, татварын дэглэмийн сонголт. Орлого нуух, хуурамч зардал гэх мэт зүйлийг хариулахгүй байх дүрмийг skill-ийн зааварт бич.

## 1. Судалгаа

а) `docs/knowledge-sources/` дахь файлуудыг унш (хууль, МТА заавар, өмнөх skill-үүд, ChatGPT-ийн зааврууд).

б) entry-ийн дансны мод, `get_workflow_guide`-ийн урсгалуудыг унш — хариулт бүр эдгээрт буух ёстой.

в) Монголын жижиг бизнесийн нягтлангийн хамгийн түгээмэл **50 асуултыг** жагсаа (өгсөн материал + web search: нягтлангийн форум, МТА-ийн FAQ). Давтамжаар эрэмбэл.

## 2. Мэдлэгийн сангийн бүтэц (docs/knowledge/)

- `tax/` — НӨАТ, ААНОАТ, ХАОАТ, НДШ, суутгал, татварын дэглэмүүд (жижиг бизнесийн хялбаршуулсан дэглэм орно), тайлангийн хугацаанууд, торгууль
- `ifrs/` — НББОУС (жижиг дунд ААН-д) болон IFRS-ийн үндсэн зарчмууд: орлого хүлээн зөвшөөрөх, бараа материал, үндсэн хөрөнгө, түрээс/лизинг, валют, авлагын эрсдэл
- `scenarios/` — практик тохиолдлууд, тус бүр нэг файл: нөхцөл байдал → хуулийн үндэслэл → IFRS зарчим → журналын бичилт (Дт/Кт, entry-ийн дансны дугаараар) → татварын нөлөө → entry дээр хийх алхам (workflow + tool + UI guide линк) → түгээмэл алдаа. **Эхний ээлжинд 50 асуултаас 20-ийг бүрэн бич.**
- `optimization/` — хууль ёсны татварын оновчлол, сэдэв бүрээр
- `glossary.md` — нэр томьёо (монгол/англи), «буцаалт» гэх мэт entry-ийн стандарт хэллэг

Файл бүр 500–1500 үг, нэг сэдэв. Дансны дугаар entry-ийн бодит дансны модтой тохирно.

## 3. Хүргэлтийн хэлбэр (нэг эх сурвалж, гурван гаралт)

1. **entry MCP** — `search_knowledge(query)` болон `get_knowledge(topic)` гэсэн 2 tool нэм (MCP resources-ийг `entry://knowledge/{path}` хэлбэрээр давхар нээж болно, гэхдээ **tool заавал байна** — ChatGPT resources-ийг муу дэмждэг). `PLAN-ai-layer.md`-тэй уялдуул.
2. **Claude Skill багц** — SKILL.md + references/ (Claude.ai, Claude Code-д суулгаж болно). SKILL.md-д хариулах загвар, эх сурвалжийн дүрэм, хориглосон зүйл, entry-тэй холбох заавар.
3. **ChatGPT-д зориулсан knowledge файлууд** (custom GPT-д оруулах хэлбэр).

Гурвуулаа нэг `docs/knowledge/`-оос build script-ээр үүсдэг байх.

> Бизнесийн тэмдэглэл: файлаар тараасан хувилбар хэрэглэгчид үлддэг тул үнэгүй/хураангуй хувилбарт зориулна; бүрэн мэдлэгийг MCP-ийн ард (server талд) байлгаж subscription-оор өгнө. Хэрэгжилтийг Session 6-ийн `KNOWLEDGE_ONLY` түвшинтэй уялдуул.

## 4. Хариулах загвар (skill-ийн зааварт орно)

Асуулт бүрд: (1) товч хариулт, (2) хуулийн үндэслэл эх сурвалжтай, (3) бүртгэлийн бичилт, (4) татварын нөлөө, (5) entry дээр хийх алхам, (6) нягтлан/татварын зөвлөхтэй зөвлөх шаардлагатай тохиолдлыг заах. Мэдэхгүй бол "мэдэхгүй" гэж хэлэх, таамаглахгүй.

## 5. Шинэчлэлийн процесс

Хууль өөрчлөгдөхөд яаж шинэчлэх (нэг файл засах → 3 гаралт дахин build), жил бүрийн тоон утгын хяналтын жагсаалт, нягтлангийн хяналтын checklist.
