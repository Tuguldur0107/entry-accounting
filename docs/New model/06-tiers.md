# Даалгавар: entry-ийн гурван борлуулалтын түвшнийг техникээр хэрэгжүүлэх төлөвлөгөө

**ЭХЛЭЭД** `PLAN.md`-г унш (архитектур, event, API давхарга). Түүнтэй зөрчилдөхгүй байх ёстой.

Зорилго: **нэг кодын сан** дээр гурван түвшний харилцагчид үйлчлэх. Тусдаа хувилбар хөгжүүлэхгүй, ялгаа нь зөвхөн entitlement (эрхийн тохиргоо)-оор шийдэгдэнэ.

**Түвшнүүд:**
- **SAAS**: бүрэн систем, ebarimt, тайлан экспорт, MCP (tool + workflow + ui guide + мэдлэгийн сангийн үндсэн хэсэг), 1 компани, хэрэглэгчийн тоо хязгаартай.
- **PLATFORM**: SAAS + REST API + webhook + extension + sandbox tenant + олон компани (нягтлангийн компанид) + Entry AI skill бүрэн + Entry Studio (ирээдүйд).
- **ENTERPRISE**: PLATFORM + dedicated/on-prem deploy + эх кодын лиценз (гэрээгээр, олон нийтэд нээхгүй) + SLA.
- Нэмэлт: **KNOWLEDGE_ONLY** гэсэн бага түвшин — зөвхөн мэдлэгийн MCP tool (`search_knowledge`, `get_knowledge`), нягтлан бодох өгөгдөлд хандахгүй.

**Ажлын горим:** судалж `PLAN-tiers.md` бичнэ. Код засахгүй. Тусдаа branch.

## 1. Судалгаа

а) Tenant загвар: tenant, хэрэглэгч, эрхийн загвар (role/permission) одоо хэрхэн тодорхойлогдсон? Хүснэгт, код хаана?

б) API key / MCP холболтын auth одоо хэрхэн ажилладаг, scope гэсэн ойлголт байгаа юу?

в) Feature flag эсвэл plan гэсэн ойлголт кодод байгаа эсэх?

г) Хязгаар хэмжих боломж: хэрэглэгчийн тоо, компанийн тоо, гүйлгээний тоо, MCP дуудлагын тоо — одоо тоологддог уу, лог байгаа юу?

д) Нэхэмжлэх, төлбөр (QPay гэх мэт) одоо байгаа эсэх — subscription-ийг хэрхэн хураах вэ?

## 2. Санал

1. **Entitlement загвар**: tenant бүрт plan + feature флагууд + хязгаарууд (JSON эсвэл хүснэгт). Plan нь флагуудын багц, гэхдээ tenant тус бүрд гараар дарж болдог (жишээ нь нэг харилцагчид API-г онцгойлон нээх).

2. **Шалгах нэг цэг**: `require_feature("api.rest")`, `require_limit("companies")` гэх мэт нэг л газраас шалгадаг helper. Код даяар `if plan == "platform"` гэж тараахгүй.

3. **API key scope**: `knowledge-only / read / write-draft / post / admin`. Түвшин ба scope хоёрын хамаарлын хүснэгт гарга. Extension-д өгөх default нь `write-draft`.

4. **Хязгаарын хэрэгжилт**: хатуу (блоклох) ба зөөлөн (анхааруулах) хязгаарын ялгаа. **Нягтлан бодох ажлыг дунд нь блоклохгүй байх** — сар хаах, тайлан илгээхийг хязгаараар зогсоохгүй.

5. **SmartGPS-ийн шилжилт**: одоогийн production tenant аль plan-д орох, ямар ч тасалдалгүй байх. Default нь хамгийн өргөн эрх, дараа нь гараар тохируулна.

6. **Usage metering**: MCP дуудлага, extension ажиллалт, компанийн тоог тоолж хадгалах — үнэ тогтооход хэрэгтэй өгөгдөл. Хувийн мэдээлэл хадгалахгүй.

7. **Enterprise эх кодын лиценз**: гэрээт харилцагчид код өгөх процесс (private repo хандалт, NDA, дахин худалдахыг хориглох, шинэчлэлт merge хийх журам). Техникийн тал: тухайн харилцагчийн fork-д таны шинэчлэлтийг тогтмол өгөх арга. **Олон нийтэд open source болгохгүй** — энэ нь зөвхөн гэрээт лиценз.

8. **Trial**: 14 хоногийн үнэгүй туршилт, дуусахад өгөгдөл устгахгүй зөвхөн бичих эрх хаагдана.
