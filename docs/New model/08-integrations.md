# Даалгавар: ebarimt холболт ба төрийн тайлангийн экспортын төлөвлөгөө

**ЭХЛЭЭД** `PLAN.md`-г унш — integration adapter, domain event, credential хадгалалтын загварыг дагана.

Зорилго:
1. **ebarimt (PosAPI)** — борлуулалтын баримтыг автоматаар илгээх, буцаах, өдрийн мэдээлэл илгээх.
2. **etax, e-balance, portal.ndaatgal** — эхний ээлжинд порталд ГАРААР байршуулах боломжтой ФАЙЛ гаргах (шууд API биш).

**Ажлын горим:** судалж `PLAN-integrations.md` бичнэ. Код засахгүй. Тусдаа branch.

> **ЧУХАЛ:** ebarimt PosAPI болон тайлангийн форматыг санах ойгоос бүү бич — албан ёсны баримт бичгийг web-ээс хайж, эх сурвалжийн холбоос хавсарга. Олдохгүй бол «[ШАЛГАХ: ...]» гэж тэмдэглэ, би МТА-аас тодруулна. **Хэрэглэгчийн нууц үгээр порталд нэвтэрч scrape хийх шийдлийг САНАЛ БОЛГОХГҮЙ.**

## 1. Судалгаа

а) entry-ийн борлуулалтын урсгал (`create_arap_invoice` → `post` → inventory) дээр ebarimt баримт хаана үүсэх ёстой вэ? Буцаалт, хэсэгчилсэн төлбөр, НӨАТ-гүй борлуулалтын тохиолдлыг тооц.

б) Одоогийн өгөгдөлд ebarimt-д шаардлагатай талбарууд байгаа эсэх: харилцагчийн ТТД/регистр, барааны ангиллын код, НӨАТ-ын хувь, хэмжих нэгж, кассын аппаратын мэдээлэл. Дутуу талбаруудыг жагсаа.

в) etax (ТТ-02 болон бусад), e-balance (санхүүгийн тайлан), ndaatgal (НД-7/8) — ямар өгөгдөл шаардагддаг, entry-ийн одоогийн тайлангуудаас хэр хангагддаг вэ? Дутууг жагсаа.

г) Мөнгө хүлээн авах суваг (QPay, картын терминал) entry-д байгаа эсэх — ebarimt-ийн төлбөрийн төрөлтэй уялдана.

## 2. Санал

1. **ebarimt adapter**: PosAPI-ийн урсгал, баримт үүсгэх, буцаах, өдрийн илгээлт. Queue + retry + idempotency (нэг нэхэмжлэхэд хоёр баримт үүсэхгүй). **Offline горим**: ebarimt унасан үед баримт дараалалд хүлээгдэж, сэргэхэд илгээгдэнэ; хэрэглэгчид төлөв харагдана.

2. **Бүртгэлийн процесс**: PosAPI ашиглахад МТА-д бүртгүүлэх, гэрчилгээ авах шаардлага юу вэ — web-ээс шалгаж, алхмуудыг жагсаа, хугацааны төсөөлөлтэй.

3. **Credential**: tenant бүрийн ebarimt мэдээллийг шифрлэж хадгалах (`PLAN.md`-ийн загвараар), лог дээр хэзээ ч бүтнээр нь бичихгүй.

4. **Тайлангийн экспорт**: тайлан бүрд (ТТ-02, санхүүгийн тайлан, НД-7/8) порталын хүлээж авах форматаар файл гаргах. Формат тодорхойгүй бол [ШАЛГАХ] тэмдэглээд, эхлээд Excel/CSV гаргаж, дараа нь тааруулна.

5. **Дутуу талбаруудын миграци**: шинэ талбар нэмэхэд SmartGPS-ийн өгөгдөлд хоосон утга үлдэнэ. Expand-migrate-contract, default утга, хэрэглэгчид нөхөж бөглүүлэх урсгал (жишээ нь харилцагчийн ТТД дутуу бол анхааруулах).

6. **Тестийн орчин**: ebarimt-ийн туршилтын орчин байгаа эсэх, production руу шилжих шалгуур.

7. **Хэрэглэгчийн UI**: баримтын төлөв (илгээгдсэн / хүлээгдэж буй / алдаа), гараар дахин илгээх, буцаалтын баримт.

## 3. Гаралт

`PLAN-integrations.md`: ebarimt-ийн бүрэн урсгал диаграм, өгөгдлийн дутуу талбарын жагсаалт ба миграцийн төлөвлөгөө, adapter-ийн интерфейс, тайлан бүрийн экспортын тодорхойлолт, бүртгэлийн процессын алхмууд ба хугацаа, [ШАЛГАХ] тэмдэглэгээний жагсаалт, хэрэгжүүлэх дараалал. Монголоор, эх сурвалжийн холбоостой.
