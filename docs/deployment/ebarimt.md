# eBarimt 3.0 (PosAPI 3.0) — нэвтрүүлэлтийн заавар (операторын загвар)

Зорилтот уншигч: Entry-г харилцагчид нэвтрүүлж байгаа оператор (Entry Console)
ба харилцагчийн нягтлан. Дизайн: `docs/pos/03-ebarimt-integration-plan.md` (v2).
Эх сурвалж: ГТСМТТ УҮГ-ын «POS API 3.0 хэрэглэгчийн гарын авлага» (2023),
«Хэрэглэгчийн систем нийлүүлэгчийн 3 талт гэрээ», ТЕГ-ийн тестийн шалгах жагсаалт.

> **Гол ойлголт:** Entry-г нийлүүлэгч байгууллага нь ТЕГ-д **оператор**
> («хэрэглэгчийн систем нийлүүлэгч») гэж бүртгэлтэй. PosAPI 3.0-ийг **оператор
> өөрөө төвлөрүүлж** ажиллуулна — албан заавар §1.2: *«Нэг PosAPI-г хэд хэдэн
> этгээд ашиглан … нэг болон түүнээс дээш тооны ААН-ийг бүртгэн баримт бүртгэх
> боломжтой»*. Харилцагч бүрийн серверт PosAPI суулгах **ШААРДЛАГАГҮЙ**.

## 1. Загвар — нэг PosAPI, олон мерчант

```
Оператор (Entry нийлүүлэгч, ТТД: операторынх)
└── PosAPI 3.0 (Linux .deb, Qt; DB: QPSQL/QSQLITE; порт 7080)  ← НЭГ суулгац
      ├── Мерчант А (харилцагч №1, өөрийн ТТД)  ← Entry апп №1 → posApiUrl
      ├── Мерчант Б (харилцагч №2, өөрийн ТТД)  ← Entry апп №2 → posApiUrl
      └── …
```

- Баримт бүрд `merchantTin` = **ХАРИЛЦАГЧИЙН** ТТД (`pos_settings.ebarimtMerchantTin`);
  PosAPI операторын бүртгэлээр ТЕГ-д хүргэнэ, сугалааг PosAPI-ийн нөөцөөс олгоно
- Харилцагч бүрийн `pos_settings.ebarimtPosApiUrl` = операторын PosAPI-ийн хаяг,
  горим `server`. Entry-ийн код харилцагч бүрд ИЖИЛ — зөвхөн тохиргоо
- Гэрээний 1.9 / 4.6.10: *«нийлүүлэгчийн эрхээр үүсгэн авсан PosAPI-г бусдад
  дамжуулахыг хориглоно»* — PosAPI-ийн суулгац, нэвтрэх эрх нь оператор дээр
  үлдэнэ; харилцагчид зөвхөн HTTP хаяг өгнө (доорх §2 урсгал яг үүнийг хангана)

## 2. Харилцагчийг мерчантаар нэвтрүүлэх (оператор + харилцагч, ~10 минут)

| # | Хэн | Хаана | Юу |
|---|-----|-------|-----|
| 1 | Оператор | `https://operator.ebarimt.mn` → PosAPI жагсаалт | PosAPI-гаа **posNo**-гоор хайж олно (§4.1) |
| 2 | Оператор | «Мерчант нэмэх» | Харилцагчийн **ТТД** оруулж хайгаад хадгална → хүсэлт харилцагч руу илгээгдэнэ (§4.2) |
| 3 | Харилцагч | `https://e-invoice.ebarimt.mn` → Хүсэлт → Хүсэлт → **Pos api хүсэлт** → «Операторын холболт» — эсвэл **Ebarimt-Mobile апп → «Үйлчилгээ»** (2025-12-18-аас) | «Хүлээгдэж буй» хүсэлтийг **батална** (§4.3) |
| 4 | Оператор | PosAPI `GET /rest/info` | `merchants[]`-д харилцагчийн ТТД гарч ирсэн бол баримт үүсгэх боломжтой (§4.4) — Entry-ийн тохиргооны таб «Мерчант бүртгэл: бүртгэлтэй» гэж харуулна |

Харилцагч зөвшөөрөөгүй бол баримт `[EBARIMT_REJECTED]`-ээр буцна; Entry-ийн
eBarimt таб «Мерчант бүртгэл: ҮГҮЙ» гэж улаанаар заана.

## 3. ТТД, дүүрэг, кассын дугаар

| Зүйл | Хаанаас |
|---|---|
| Харилцагчийн **ТТД** (11/14 орон) | Харилцагчийн ETAX «Татвар төлөгчийн мэдээлэл», эсвэл Entry-д РД → ТТД лавлах (`lookup_tin`). Салбарын ТТД-ээр баримт үүсгэх боломжгүй (албан заавар) |
| **Салбарын дугаар** (`branchNo`) | Харилцагчийн e-invoice бүртгэл; нэг салбартай бол «001» г.м. |
| **Дүүргийн код** (4 орон) | ТЕГ-ийн лавлах — Entry автоматаар татна (сонголт) |
| **Кассын дугаар** (`posNo`) | Харилцагчийн ДОТООД кассын дугаар (чөлөөт мөр, албан заавар «Тухайн байгууллагын дотоод кассын дугаар»). PosAPI-ийн 8 оронтой `posNo`-той АНДУУРАХГҮЙ — тэр нь операторын консолд PosAPI хайх дугаар |

## 4. PosAPI 3.0 суулгац (оператор, нэг удаа)

- Багц: ГТСМТТ-ийн Linux `.deb` (Qt; Java БИШ). Тохиргоо `posapi.ini`:
  `db` = `QPSQL` (Postgres) / `QSQLITE`, `dbHost/dbPort/dbUser/dbPass/dbName`,
  `workDir` (унших/бичих эрхтэй, **хэзээ ч freeze хийхгүй**), `webServiceHost`,
  `webServicePort` (default 7080). Хүснэгтийг PosAPI өөрөө үүсгэдэг тул DB
  хэрэглэгч table үүсгэх эрхтэй байна
- Идэвхжүүлэлт: PosAPI суусны дараа **идэвхгүй**; оператор эрхтэй хэрэглэгч
  PosAPI-ийн web (`http://<host>:7080/web/`)-д нэвтэрч операторыг сонгон
  идэвхжүүлэхэд ТЕГ-д бүртгэгдэж сугалааны нөөц авна (§3)
- Машин **бодит сүлжээний төхөөрөмжтэй** (LAN card) байх ёстой (албан заавар
  §5) — контейнерт eth0 хангалттай, харин NIC-гүй sandbox-д ажиллахгүй
- Railway дээр: тусдаа service + volume (`workDir`) + Postgres; Entry-ээс
  `http://<service>.railway.internal:7080`. Одоогийн PROD суулгац:
  операторын өөрийн серверт (`Links.txt`) — харилцагчид тэр хаягийг өгнө
- Staging: `st-operator.ebarimt.mn`, `stg-invoice.ebarimt.mn`; тестийн
  оператор эрхийг ГТСМТТ-ээс и-мэйлээр (байгууллага, РД, холбогдох хүний
  овог/нэр/РД/утас/и-мэйл) авна
- **Албан best practice (developer портал):** PosAPI-г нийтийн сүлжээнд ил тавихгүй —
  Entry (Railway) ↔ операторын PosAPI хооронд VPN/tunnel + IP allowlist; нэг PosAPI-д
  ≤1000 мерчант, ≤100 000 баримт/өдөр, DB ping <100 мс; `posapi.ini`: `noEasyResponse = true`
  (банкны картын хялбар бүртгэлийн хариуг хүлээхгүй — `easy` талбар ажиллахгүй),
  `skipHours = 1114,1821` (шинэчлэлт оргил цагт хийгдэхгүй); **хувилбар ≥ 3.0.12**
  (2025-11-25 «яаралтай») — тохиргооны таб сүүлийн баримтын хариуны `version`-ийг харуулж
  доош бол улаанаар анхааруулна
- ТЕГ-ийн нийтийн лавлах (`api.ebarimt.mn`) ЗӨВХӨН Монголын IP — гадаад бүсийн Entry
  серверт `EBARIMT_PUBLIC_API_BASE` (§7)

## 5. Entry дээр тохируулах (харилцагч бүрд, 5 минут)

1. **Борлуулалт → Тохиргоо → eBarimt**: ТТД, салбар, дүүрэг, posNo, PosAPI URL
   (операторын), горим `server` → [Хадгалах] → [Холболт шалгах] — `/rest/info`
   хариулж, «Мерчант бүртгэл: бүртгэлтэй» гарах ёстой
2. **Төлбөрийн хэлбэр бүрд eBarimt код** (`CASH`, `PAYMENT_CARD` …)
3. **Бараа бүрд ангилалын код (7 орон)** — ҮСХ-ны «Бүтээгдэхүүн, үйлчилгээний
   нэгдсэн ангилал»-ын 4-р багана; бүлэгт оноовол бараа өвлөнө. НӨАТ-гүй / 0%
   бараанд **татварын бүтээгдэхүүний код (3–5 орон)** — ТЕГ-ийн албан жагсаалтаас
   сонгогч (`lib/ebarimt/tax-product-codes.ts`: чөлөөлөгдөх 305–446, 0% 501–507)
4. **Бэлэн байдлын блок** цэвэр болмогц «eBarimt автомат баримт» switch асна
   (дутуу байвал switch идэвхгүй, server тал ч татгалзана)

## 6. Ажиллах зарчим — албан заавартай тулгасан

- **Илгээлт:** борлуулалт батлагдмагц дараалалд орж (`pos_ebarimt_submissions`)
  server горимд **шууд** илгээгдэнэ (≤8 сек хүлээнэ) — хариу ирвэл баримт
  **ДДТД + сугалаа + QR**-тай хэвлэгдэнэ; хэтэрвэл баримт QR-гүй гарч, илгээлт
  ард үргэлжилнэ. Борлуулалт илгээлтээс болж ХЭЗЭЭ Ч зогсохгүй
- **Сугалаа ба QR ХАДГАЛАГДАХГҮЙ** — албан заавар §5: *«lottery болон qrData
  талбаруудын мэдээллийг хэрэглэгчийн системд хадгалахыг хориглоно»*; ТЕГ-ийн
  тестийн checklist «QR код хадгалахгүй». Иймд **дахин хэвлэхэд зөвхөн ДДТД**
  гарна; `pos_ebarimt_submissions.response`-оос ч хасагдана (`stripReceiptSecrets`)
- **Хэсэгчилсэн буцаалт** — §5 «Баримтын засвар»: `inactiveId` = сүүлийн ДДТД
  бүхий ШИНЭ бичилт (эхийг орлоно, **сугалаа дахин олгохгүй**, дараагийн засвар
  сүүлийн ДДТД-г гинжилнэ). **Бүтэн буцаалт** — §6 `DELETE /rest/receipt`
- **72 цаг** (гэрээ 3.6): PosAPI ТЕГ рүү өөрөө илгээнэ; өдөр бүр 23:30 УБ
  `sendData`; ТЕГ рүү 48 цагаас удаан илгээгдээгүй бол анхааруулга, 72 цагаас
  дээш бол улаан (`pos.ebarimt_send_stale`)
- **Сугалааны нөөц** (`leftLotteries`) 200-аас доош бол анхааруулга, 0 бол
  улаан (`pos.ebarimt_lottery_low`); PosAPI-д хүрэхгүй бол `pos.ebarimt_posapi_down`
  — гурвуулаа өдөрт нэг, POS-ийн бичих эрхтэй гишүүдэд (самбар + мэдэгдэл)
- Амжилтгүй илгээлт backoff (15с → 1мин → 5мин → 30мин → 2ц, max 20), 3
  дараалсан алдаанд `pos.ebarimt_failed`; зассаны дараа [Дахин илгээх]
- Гараар ДДТД бичсэн борлуулалт (`manual`) автомат илгээлтэд ОРОХГҮЙ; `sent`
  баримтын ДДТД-г гараар засах ХОРИОТОЙ

## 7. Env / cron

| Тохиргоо | Үүрэг |
|---|---|
| `EBARIMT_WORKER=off` | In-process worker (20 сек) унтраана — гадаад cron-оор л ажиллуулах бол |
| `CRON_SECRET` | `POST /api/cron/ebarimt?job=process\|senddata\|all` нээнэ (Bearer) |
| `EBARIMT_PUBLIC_API_BASE` | ТЕГ-ийн нийтийн лавлахын суурь хаяг — `api.ebarimt.mn` **зөвхөн Монголын IP**-ээс хандагддаг тул гадаад бүсийн (Railway) серверт Монголд байрлах прокси / операторын PosAPI сервер дээрх reverse proxy-ийн хаяг өгнө (замууд ижил: `/getTinInfo`, `/getInfo`, `/getBranchInfo`). Хоосон бол default |

Ямар ч тохиргоогүй бол in-process worker ажиллана (`lib/ebarimt/ticker.ts`).

## 8. Хяналт (Entry Console)

`GET /api/health` → `ebarimt`: `enabledOrganizations`, `serverModeOrganizations`,
`pending`, `failed`, `lastSentAt` — **ТТД, нууц, дүн, сугалаа БАЙХГҮЙ**.
Тохиргооны таб / `get_ebarimt_status`: PosAPI-ийн оператор, posNo, үлдсэн сугалаа,
ТЕГ рүү сүүлд илгээсэн, мерчант бүртгэлтэй эсэх.

## 9. Асуудал шийдвэрлэх

| Шинж | Шалтгаан / арга |
|---|---|
| «PosAPI-д хүрсэнгүй» | service унтарсан / URL буруу / firewall (Railway → операторын сервер рүү гарах зам). [Холболт шалгах] |
| «Мерчант бүртгэл: ҮГҮЙ» | Харилцагч операторын хүсэлтийг батлаагүй (§2 алхам 3 — e-invoice эсвэл Ebarimt-Mobile апп «Үйлчилгээ» цэсээр) |
| Кассын ААН лавлах «ТЕГ-ийн лавлахад холбогдож чадсангүй» | Сервер гадаад бүсэд — `EBARIMT_PUBLIC_API_BASE` (§7); эсвэл ТЕГ регистрээр лавлахыг хязгаарласан (2026-06-15) — кассчин ТТД-г шууд оруулна (харилцагчийн ETAX «Татвар төлөгчийн мэдээлэл») |
| Цуцлалт татгалзагдав (B2B / нэхэмжлэх) | ТЕГ: DELETE зөвхөн B2C_RECEIPT, иргэн баталгаажуулаагүй баримтад; баталгаажсан бол иргэн апп-аас зөвшөөрөх хүртэл «Баталгаажаагүй буцаалт» — ТЕГ-тэй тохирно |
| Readiness анхааруулга «код албан жагсаалтад байхгүй» | `payments[].code` албан: CASH, PAYMENT_CARD, BANK_TRANSFER, BANK_TRANSFER_QPAY — хэлбэрийн кодыг засах (блоклохгүй) |
| `[EBARIMT_UNMAPPED_ITEM]` | ангилалын код байхгүй → карт/бүлэгт оруулаад [Дахин илгээх] |
| `[EBARIMT_TAX_PRODUCT_CODE]` | НӨАТ-гүй/0% бараанд 3 оронтой код байхгүй (албан жагсаалтаас) |
| `[EBARIMT_UNMAPPED_PAYMENT]` | төлбөрийн хэлбэрт код оноогоогүй |
| `[EBARIMT_TOTAL_MISMATCH]` | мөрийн Σ ≠ төлбөрийн Σ — тайлангаас баримтыг шалга |
| Сугалаа дууссан | PosAPI ТЕГ-тэй холбогдож нөөцөө сэргээгээгүй — сүлжээ, `sendData` |
| Цуцлалт татгалзагдав | ТЕГ-ийн хугацааны хязгаар — буцаалт GL-д хэвээр, ТЕГ-тэй тохирно |
