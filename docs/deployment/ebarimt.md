# eBarimt 3.0 (PosAPI 3.0) — нэвтрүүлэлтийн заавар

Зорилтот уншигч: Entry-г харилцагчид нэвтрүүлж байгаа оператор (Entry Console)
ба харилцагчийн нягтлан. Дизайн: `docs/pos/03-ebarimt-integration-plan.md`.

> **Анхаар:** PosAPI 3.0 нь ТЕГ-ийн олгодог, **мерчантын талд суудаг**
> үйлчилгээ. Entry түүнийг агуулдаггүй — зөвхөн HTTP-ээр дууддаг. Суулгац,
> хувилбарын шинэчлэлт, ТЕГ-ийн зөвшөөрөл нь мерчантын (харилцагчийн) үүрэг.

## 1. Урьдчилсан нөхцөл (харилцагч ТЕГ-ээс авна)

| Зүйл | Хаанаас | Entry-д хаана |
|---|---|---|
| Мерчантын ТТД (11/14 орон) | ebarimt.mn мерчант портал | Борлуулалт → Тохиргоо → eBarimt |
| Салбарын дугаар (branchNo) | мөн тэндээс | " |
| Дүүргийн код (4 орон) | ТЕГ-ийн лавлах (Entry автоматаар татна) | " |
| Кассын дугаар (posNo) | «PosAPI 3.0 хүсэлт» батлагдахад | " |
| PosAPI 3.0 суулгац | ТЕГ | доорх §2 |

ТЕГ-ийн «PosAPI 3.0 хүсэлт»-ийг мерчант порталаас гаргаж батлуулсны дараа л
дээрх дугаарууд хүчинтэй. Тестийн орчин (`stg-invoice.ebarimt.mn`) байгаа бол
эхлээд тэндээс турших.

## 2. Топологи — хоёр горим

### (а) `server` горим — ЗӨВЛӨЖ БАЙНА

PosAPI-г харилцагчийн **Railway төсөлд тусдаа service** болгож суулгана; Entry
апп дотоод сүлжээгээр дууддаг. Кассын компьютерт юу ч суулгахгүй, олон касс
(posNo) нэг PosAPI-г хуваалцана.

```
Railway төсөл (харилцагч)
├── entry-accounting   ← EBARIMT_POSAPI_URL=http://posapi.railway.internal:7080
├── posapi             ← ТЕГ-ийн PosAPI 3.0 (Java), volume: /app/data
└── Postgres
```

- `posapi` service: ТЕГ-ийн олгосон багцаас Docker image бүтээнэ (Java 11+),
  `7080` порт, дотоод сан (`data`) нь **volume** дээр байх ЁСТОЙ — сүлжээгүй
  үед хуримтлагдсан баримт тэнд хадгалагдана
- Мерчант порталд бүртгэх IP/хаяг нь тэр service-ийн гадаад хаяг
- Entry-ийн тохиргоонд `PosAPI URL` = `http://posapi.railway.internal:7080`,
  горим `server`

### (б) `browser` горим — нөөц зам

PosAPI кассын компьютерт суусан (ТЕГ-ийн стандарт суулгац). Кассын дэлгэц
(браузер) `http://localhost:7080`-д өөрөө хандаж, хариуг Entry рүү бичнэ.
Тохиргоонд `PosAPI URL` = `http://localhost:7080`, горим `browser`.

Хязгаарлалт: кассын компьютер унтарвал дараалал зогсоно (баримт алдагдахгүй —
дараа нь дэлгэц нээгдмэгц илгээгдэнэ); AI/MCP-ээр бүртгэсэн борлуулалт
браузер нээгдэх хүртэл хүлээнэ.

## 3. Entry дээр тохируулах (5 минут)

1. **Борлуулалт → Тохиргоо → eBarimt**: ТТД, салбар, дүүрэг, posNo, PosAPI URL,
   горим → [Хадгалах] → [Холболт шалгах] (PosAPI `/rest/info` хариулах ёстой)
2. **Төлбөрийн хэлбэр бүрд eBarimt код** (ТЕГ-ийн жагсаалтаас: `CASH`,
   `PAYMENT_CARD` …). Код оноогоогүй хэлбэрээр зарсан борлуулалт
   `[EBARIMT_UNMAPPED_PAYMENT]` алдаа өгнө — баримт илгээгдэхгүй
3. **Бараа бүрд ТЕГ-ийн ангилалын код (7 орон)**. Бүлэг (`inventory_categories`)
   дээр нэг удаа оноовол бараа нь өвлөнө. НӨАТ-гүй / 0%-ийн бараанд
   **татварын бүтээгдэхүүний код (3 орон)** мөн заавал
4. Бүх дутуу цэгцэрсний дараа **«eBarimt автомат баримт»** switch-ийг АСААНА

**Бэлэн байдлын шалгалт (АСААХААС ӨМНӨ автомат).** Тохиргооны таб нь мерчантын
талбаруудаас гадна *кодын* дутууг тоолж харуулна: ангилалын кодгүй идэвхтэй
бараа (бүлгээс өвлөх нь тооцогдоно), татварын бүтээгдэхүүний кодгүй НӨАТ-гүй /
0% бараа, eBarimt кодгүй идэвхтэй төлбөрийн хэлбэр — тоо + эхний нэрсээр.
Аль нэг нь үлдсэн бол switch **идэвхгүй** бөгөөд server тал ч татгалзана
(`updatePosSettings`). Шалтгаан: эдгээр алдаа урьд нь зөвхөн БОРЛУУЛАЛТ
БОЛСНЫ ДАРАА, дараалалд async гарч ирдэг байсан — кассчин үйлчлүүлэгчийг
баримтгүй үдэх эрсдэлтэй. Логик нь ЦЭВЭР `lib/ebarimt/readiness.ts`
(`tests/ebarimt-readiness.test.ts`); AI/MCP-ээс `get_ebarimt_status` мөн
ижил жагсаалтыг буцаана.

## 4. Ажиллах зарчим

- Борлуулалт батлагдмагц дараалалд (`pos_ebarimt_submissions`) мөр үүсэж
  **async** илгээгдэнэ — **борлуулалт хэзээ ч хүлээхгүй, зогсохгүй**
- ДДТД / сугалаа / QR ирмэгц борлуулалтад бичигдэж, баримт дахин хэвлэхэд
  QR-тайгаа гарна. Илгээгдэх хооронд баримтад «eBarimt: илгээж байна…»
- Амжилтгүй бол backoff-оор (15с → 1мин → 5мин → 30мин → 2ц) дахин оролдоно;
  3 дараалсан алдаанд POS-ийн бичих эрхтэй гишүүдэд мэдэгдэл
  (`pos.ebarimt_failed`) явна; шалтгааныг зассаны дараа [Дахин илгээх]
- **Буцаалт:** эх ДДТД ТЕГ-д цуцлагдаж, үлдсэн мөр байвал шинэ баримт илгээгдэнэ
- Өдөр бүр 23:30 (УБ) PosAPI-ийн `sendData` — дотоод санд үлдсэнийг ТЕГ рүү
- Гараар ДДТД бичсэн борлуулалт (`manual`) автомат илгээлтэд ОРОХГҮЙ (давхар
  баримт үүсэхгүй); илгээгдсэн баримтын ДДТД-г гараар засах ХОРИОТОЙ

## 5. Env / cron

| Тохиргоо | Үүрэг |
|---|---|
| `EBARIMT_WORKER=off` | In-process worker (20 сек) унтраана — гадаад cron-оор л ажиллуулах бол |
| `CRON_SECRET` | `POST /api/cron/ebarimt?job=process\|senddata\|all` нээнэ (Bearer) |

Ямар ч тохиргоогүй бол in-process worker ажиллана (`lib/ebarimt/ticker.ts`) —
Railway cron шаардлагагүй.

## 6. Хяналт (Entry Console)

`GET /api/health` → `ebarimt` блок: `enabledOrganizations`,
`serverModeOrganizations`, `pending`, `failed`, `lastSentAt`. **ТТД, нууц,
баримтын дүн БАЙХГҮЙ** — зөвхөн тоолуур. `failed > 0` эсвэл `pending` удаан
өсөж байвал операторын анхаарал шаардана (§3.1 docs/pos/03).

## 7. Асуудал шийдвэрлэх

| Шинж | Шалтгаан / арга |
|---|---|
| «PosAPI-д хүрсэнгүй» | service унтарсан / URL буруу / firewall. [Холболт шалгах] |
| `[EBARIMT_UNMAPPED_ITEM]` | барааны ангилалын код байхгүй → карт эсвэл бүлэгт оруулаад [Дахин илгээх] |
| `[EBARIMT_TAX_PRODUCT_CODE]` | НӨАТ-гүй/0% бараанд 3 оронтой код байхгүй |
| `[EBARIMT_UNMAPPED_PAYMENT]` | төлбөрийн хэлбэрт eBarimt код оноогоогүй |
| `[EBARIMT_TOTAL_MISMATCH]` | мөрийн Σ ≠ төлбөрийн Σ (бөөрөнхийлөл) — тайлангаас баримтыг шалга, дэмжлэгт хандана |
| ТЕГ «Мерчант олдсонгүй» | ТТД / posNo / салбар порталын бүртгэлтэй таарахгүй |
| Цуцлалт татгалзагдав | ТЕГ-ийн хугацааны хязгаар хэтэрсэн — буцаалт нь GL-д хэвээр, eBarimt-ийг ТЕГ-тэй тохирно |
