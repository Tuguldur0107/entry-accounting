# Анхны мэдээлэл (master data) — загвар файлууд

Харилцагчийн хуучин системээс (Excel, 1C, Diamond, гараар) мэдээллээ эдгээр
загварын баганын нэрээр бэлдээд Claude Cowork / Claude Code-д өгнө.
Cowork нь `.claude/skills/master-data-import/SKILL.md` зааврын дагуу MCP
tools-оор системд оруулна. **Баганын НЭР чухал, дараалал биш.**

| # | Файл | MCP tool (batch, max 100/дуудлага) | Тэмдэглэл |
|---|------|-----------------------------------|-----------|
| 1 | `01-gl-accounts.csv` | `create_gl_accounts_batch` | Стандарт дансны мод аль хэдийн бий (Тохиргоо → ЕЖ тохиргоо → "Стандарт данс sync"). Зөвхөн НЭМЭЛТ данс энд |

| 5 | `05-cash-accounts.csv` | `create_cash_account` (мөр бүрд) | `glAccount` нь 1-р файлд/стандарт дансанд байх ёстой. `openingBalance` нь 8-р файлын дүнтэй ТЭНЦЭХ ёстой |

## Нээлтийн үлдэгдлийн дүрэм

1. **Огноо** — нэвтрүүлэлтийн өмнөх өдөр (жишээ: 2026-10-01-нээс эхэлбэл
   2026-09-30). Тэр сар хаагдаагүй байх ёстой.
2. **Нэг журнал, ноорог** — `create_journal_voucher` `externalRef:
   "opening-balance:YYYY-MM-DD"` (давхар оруулахаас хамгаална).
3. **АР/АП дэлгэрэнгүй** — 13110000 / 31000001-ийн нийт дүнг харилцагч
   тус бүрээр `create_arap_invoices_batch`-аар (огноо = эх нэхэмжлэхийн
   огноо, `externalRef` = хуучин системийн дугаар) оруулна. Ингэснээр aging
   тайлан зөв гарна. Тэгвэл нээлтийн журналд 13110000/31000001 мөрийг
   ОРУУЛАХГҮЙ (нэхэмжлэх батлагдахад GL-д өөрөө бичигдэнэ) — хоёр дахин
   тоологдохоос болгоомжил.
4. **Бараа материал** — 14110000-ийн дүнг бараа × агуулах × тоо × нэгж
   өртгөөр `create_inventory_movement` (орлого, өртөгтэй) оруулна. Мөн адил
   нээлтийн журналд давхардуулахгүй.
5. **Касс/банк** — `05-cash-accounts.csv` `openingBalance` нь кассын дэд
   дэвтрийн үлдэгдэл; нээлтийн журналын 11210000/11000001 мөр GL-ийнх.
   Хоёулаа ижил дүнтэй байх ёстой — `reconcile_modules` tool шалгана.
6. Дууссаны дараа `get_trial_balance` (нээлтийн огноогоор) хуучин системийн
   балансын тайлантай мөр мөрөөр тулгана.
