Entry Accounting нь **FSL-1.1-Apache-2.0** (Functional Source License) дор
тараагддаг. Хуулийн хүчинтэй эх бичвэр нь [LICENSE](../../LICENSE) —
энэ хуудас нь зөвхөн энгийн тайлбар, гэрээний оронд ороогүй.

## Богино хариу

| Үйлдэл | Зөвшөөрөгдөх үү |
|--------|-----------------|
| Өөрийн компанийн нягтлан бодох бүртгэлд ашиглах | ✅ |
| Кодыг өөрийн хэрэгцээнд өөрчлөх (vibe coding, `custom/`) | ✅ |
| Өөрийн сервер, өөрийн cloud дээр байршуулах | ✅ |
| Салбар компани, охин компаниудаа энэ дээр ажиллуулах | ✅ |
| Хөлсний хөгжүүлэгчээр өөрчлүүлэх | ✅ |
| Өөрчилсөн кодоо өөртөө хаалттай байлгах | ✅ |
| **Үүнийг бүтээгдэхүүн болгож бусад компаниуд руу зарах** | ❌ |
| **Үүн дээр суурилсан SaaS нээж гуравдагч этгээдэд үйлчлэх** | ❌ |
| Entry Accounting нэр, лого ашиглах | ❌ (тусдаа зөвшөөрөл) |

Товчхондоо: **өөрийн бизнест юу ч хий, гэхдээ үүнийг өрсөлдөгч бүтээгдэхүүн
болгож бүү зар.**

## Нягтлан / аудитын фирмүүдийн хувьд

FSL «дотоод хэрэглээ»-г зөвшөөрдөг. Нягтлан бодох фирм клиентийнхээ бүртгэлийг
хөтөлж байгаа нь дотоод хэрэглээ үү, үйлчилгээ үү гэдэг нь маргаантай тул
шугамыг ил тодорхойлов. Шалгуур нь энгийн: **клиент өөрөө нэвтэрдэг үү, үгүй
юу.**

| Тохиолдол | Лиценз |
|-----------|--------|
| Компани өөрийн бүртгэлдээ ашиглана (хэдэн ч салбартай) | Үнэгүй |
| Нягтлан фирм клиентийн дата оруулна, клиент нэвтрэх эрхгүй | Үнэгүй |
| Клиент өөрөө нэвтэрч ашиглана, эсвэл клиентэд төлбөртэй хандалт өгнө | Partner лиценз |
| Entry-г өөр нэрээр брэндлэн зарна | Partner лиценз + брэндийн зөвшөөрөл |

Дунд хоёр мөрийн ялгаа нь: та үйлчилгээгээ зарж байна уу (зөв), эсвэл манай
системийг зарж байна уу (Partner лиценз хэрэгтэй).

## Хоёр жилийн дараа нээгдэнэ

Хувилбар бүр гарснаасаа хойш **хоёр жилийн дараа автоматаар Apache 2.0**
болж бүрэн нээлттэй болно. Өөрөөр хэлбэл өнөөдрийн код 2028 онд ямар ч
хязгаарлалтгүй болно. Энэ нь та манайхаас хамаарч үлдэхгүй гэсэн баталгаа.

## Яагаад энэ лиценз вэ

Бидний загвар нь: та кодоо эзэмшинэ, өөрчилнө, өөрийн серверт тавина, биднээс
хамаарахгүй. Бид сургалт, шинэчлэлт, дэмжлэгээр орлого олно.

Энэ загварт нэг л эрсдэл бий: хэн нэгэн кодыг аваад Монголын бусад компаниудад
Entry Accounting-ийг зарж эхлэх. FSL яг үүнийг хориглодог бөгөөд өөр юуг ч
хориглодоггүй. Ижил лицензийг Sentry ашигладаг; ойролцоо загварыг HashiCorp
(BUSL), Elastic (ELv2) хэрэглэдэг.

## Шинэчлэлт авах эрх

Кодын лиценз ба **шинэчлэлтийн урсгал хоёр өөр зүйл.**

- Танд өгөгдсөн хувилбар үүрд таных. Гэрээ дуусах, төлбөр зогсоход ажиллахаа
  болихгүй, ямар нэг «унтраах товч» байхгүй.
- Харин **шинэ хувилбарууд** нь идэвхтэй захиалгын хүрээнд ирнэ. Техникийн
  талаас: таны repo-д core-оос татах эрх (deploy key) олгогдсон байх үед
  `upstream-sync` ажиллаж шинэ хувилбарыг PR болгож ирүүлнэ. Захиалга
  зогсвол тэр эрх цуцлагдаж шинэчлэлт ирэхээ болино — байгаа код хэвээр.

## `custom/` доторх код таных

`custom/` хавтас дотор та (эсвэл таны хөгжүүлэгч) бичсэн код нь таны өмч.
Бид түүн дээр эрх нэхэхгүй, sync хийхдээ хөндөхгүй. Дэлгэрэнгүй:
[custom/README.md](../../custom/README.md).

Entry таны repo-ийн техникийн эзэн (GitHub owner) боловч энэ нь **кодыг тань
ашиглах эрх өгдөггүй**. Таны кодыг core-д авах ганц зам — та өөрөө зөвшөөрөх:

| Зам | Хэрхэн | Хэзээ тохиромжтой |
|---|---|---|
| PR илгээх | Public core-ыг fork → cherry-pick → PR, `git commit -s` (DCO) | Өөрөө хийж дуусгамаар бол |
| Зөвшөөрлийн файл | `custom/UPSTREAM-CONSENT.md`-д багцаа бичиж өөрөө commit хийнэ; Entry авч ерөнхий болгоно | Завгүй бол |

Хоёулаа **онцгой бус** эрх — зохиогчийн эрх таных хэвээр, кодоо хаана ч
ашиглаж болно. Нөхцөл, загвар: [CONTRIBUTING.md](../../CONTRIBUTING.md),
[UPSTREAM-CONSENT.template.md](UPSTREAM-CONSENT.template.md).

Санаа, шаардлага нь зохиогчийн эрхээр хамгаалагддаггүй — «олон харилцагч
ийм зүйл хийж байна» гэдгийг ажиглаад Entry өөрийн ерөнхий хувилбарыг шинээр
бичиж болно; таны кодыг хуулахгүй.

## Асуулт

Лицензийн хүрээнээс давсан хэрэглээ (жишээ нь та өөрөө үүнийг үйлчлүүлэгч
нартаа санал болгохыг хүсвэл) — бидэнтэй ярилцана уу. Тусдаа арилжааны
лиценз олгох боломжтой.
