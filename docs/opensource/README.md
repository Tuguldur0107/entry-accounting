# Open Source болгох хөгжүүлэлтийн спекүүд

Энэ хавтас нь Entry-г нээлттэй болгоход шаардлагатай хөгжүүлэлтийн **ажлын
даалгаврууд** (спек). Claude Code-той хамтарч ажиллахад зориулагдсан —
фаз бүр нэг спек файлтай, Claude Code тухайн файлыг уншаад ажиллана.

Бизнесийн үндэслэл: [`docs/OPEN-SOURCE-STRATEGY.md`](../OPEN-SOURCE-STRATEGY.md)

> **2026-08-08:** Спекүүдийн «Одоогийн байдал» хэсгүүд кодын өнөөгийн
> байдалд тааруулагдав (НӨАТ, Цалин, Сар хаалтын wizard, Audit log,
> банкны тулгалт хэрэгжсэн; schema 55 хүснэгт болсон). Фаз 04-ийн ажил
> «урьдчилан суурь тавих»-аас «calc.ts-ийн тогтмолуудыг нүүлгэх» болж
> тодорхойлогдсон.

## Claude Code-той ажиллах дүрэм

1. **Нэг session = нэг фаз.** Хоёр фазыг нэг дор бүү хийлгэ.
2. Prompt-уудыг [00-claude-code-prompts.md](00-claude-code-prompts.md)-оос
   хуулж ашиглана.
3. Claude Code эхлээд **plan гаргана, чи баталсны дараа** кодлоно
   (Plan mode / "эхлээд төлөвлөгөө гаргаж надаар батлуул" гэж шаард).
4. Фаз дуусахад Claude Code:
   - Спекийн "Хүлээн авах шалгуур" бүрийг шалгасан байна
   - `npm run build` + байгаа тестүүд амжилттай байна
   - Энэ README-ийн статус хүснэгтийг шинэчилнэ (⬜ → ✅ + огноо)
5. **01-р фазын өмнө DB backup ЗААВАЛ** (Railway дээр snapshot эсвэл
   `pg_dump`). Migration бүтэлгүйтвэл сэргээх зам байх ёстой.
6. Спек өөрчлөх шаардлага гарвал (хийж явцад илүү сайн шийдэл олдвол)
   Claude Code эхлээд спек файлыг засаж, тайлбар бичээд, дараа нь кодлоно —
   спек ба код зөрөхгүй байх ёстой.

## Спекийн бүтэц (бүх файлд ижил)

- **Зорилго** — юуны төлөө
- **Одоогийн байдал** — кодын өнөөгийн бодит байдал
- **Хийх ажил** — үе шаттай даалгавар
- **Хатуу дүрэм** — зөрчиж болохгүй зүйлс
- **Хамрахгүй** — энэ фазад ХИЙХГҮЙ зүйлс (scope creep хаалт)
- **Хүлээн авах шалгуур** — дуусгасны тодорхойлолт
