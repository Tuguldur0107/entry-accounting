# Фаз 04 — Зохицуулалтын дата давхарга (Regulatory)

## Зорилго

Татварын хувь, НДШ хязгаар, ХАОАТ шатлал, тайлангийн хугацаа зэрэг **хуулиас
хамаардаг бүх тоог** кодоос салгаж, огноогоор (effective-date) lookup хийдэг
нэг давхаргад төвлөрүүлэх. Хоёр үр дүн:

1. Хууль өөрчлөгдөхөд кодын өөрчлөлтгүйгээр, дата шинэчлэлтээр шийдэгдэнэ
2. Ирээдүйд «шинэчлэлтийн feed» гэдэг төлбөртэй үйлчилгээний суурь болно —
   fork хийсэн хэрэглэгч кодыг авна, харин баталгаажсан шинэчлэлтийг
   захиалгаар авах сонголттой болно

CLAUDE.md §10 (Effective date guardrail)-ийн бүрэн хэрэгжилт.

## Одоогийн байдал

*Шинэчилсэн: 2026-08-08 — VAT/Payroll модуль ХЭРЭГЖСЭН тул энэ фазын ажил
"урьдчилан суурь тавих"-аас "байгаа тогтмолуудыг нүүлгэх" болж өөрчлөгдөв.*

- **НӨАТ хэрэгжсэн:** хувь нь `vat_settings.vatRatePercent` (default 10) —
  аль хэдийн дата-driven; бүртгэлийн босго 400M нь
  `lib/actions/vat.ts`-д тогтмол (`VAT_REGISTRATION_THRESHOLD_MNT`) →
  `vat.json` руу нүүнэ
- **Цалин хэрэгжсэн:** доод цалин / cap үржүүлэгч / татваргүй босго нь
  `payroll_settings`-д (дата-driven); харин **НДШ хувиуд (8.5/0.8/0.2/2.0
  + АО тал) болон ХАОАТ шатлал/хөнгөлөлтийн хүснэгт нь
  `lib/payroll/calc.ts`-ийн тогтмолууд**, effective-date нь оноор
  салгасан if (2025 flat / 2026 шатлал) — энэ фазын ГОЛ нүүлгэх зүйл.
  Тестүүд (`tests/payroll-calc.test.ts`, worked-example) шилжилтийн үед
  хамгаалалт болно
- Тайлангийн хугацаанууд (НДШ 5, ХАОАТ/НӨАТ 10, алданги 0.1%/хоног) —
  `lib/vat/return.ts` `vatDeadlineOf` + UI текстүүдэд тархсан →
  `deadlines.json`
- `knowledge/01-онол-хууль-стандарт/tax/`, `.../payroll/` — эх сурвалж
- Effective-date guardrail: `knowledge/.../guardrails/effective-date.md`

## Хийх ажил

### Шат 1 — Дата формат

`regulatory/mn/` хавтас (repo root, ирээдүйд тусдаа repo болгож салгахад
бэлэн байхаар core-оос хараат бус):

```
regulatory/mn/
├── vat.json                НӨАТ хувь, босго
├── social-insurance.json   НДШ хувиуд (ажилтан/ажил олгогч задаргаатай),
│                           cap томьёо (minimumWage × 10), доод цалин
├── pit.json                ХАОАТ шатлал, хөнгөлөлт
├── cit.json                ААНОАТ шатлал
├── deadlines.json          Тайлан/төлбөрийн хугацаанууд, хоцролтын алданги
└── meta.json               Хувилбар, огноо, эх сурвалжийн линкүүд
```

Бүх файл нэг бүтэцтэй: утга бүр **хугацааны интервалтай** массив:

```json
{
  "vatRate": [
    { "effectiveFrom": "2016-01-01", "value": 0.10,
      "source": "НӨАТ-ын тухай хууль ...", "note": "" }
  ]
}
```

Дүрэм: интервалууд салангид, цоорхойгүй байхыг validator шалгана.

### Шат 2 — Lookup давхарга

`lib/regulatory/index.ts`:

```ts
getRegulatoryValue(key: string, date: string): number | RegValue
// Тухайн огноонд хүчинтэй утгыг буцаана.
// Хамрах интервал ОЛДОХГҮЙ бол throw — таамаглаж БОЛОХГҮЙ
// (effective-date guardrail: хамаарах огноогүй тооцоолол хийхгүй)
```

- Бүрэн unit тесттэй: интервалын зах, ирээдүйн огноо (дата байхгүй → алдаа),
  хуучин огноо
- Validator script: `npm run regulatory:validate` — schema, интервалын
  цоорхой/давхцал, эх сурвалж заавал байх
- JSON-уудыг build-д bundle хийнэ (сервер талд sync унших боломжтой)

### Шат 3 — Хэрэглээ рүү холбох

- Кодод одоо байгаа тогтмолуудыг эрж ол (`grep` 0.1, 0.115, 792000,
  7920000 г.м.) — олдвол энэ давхаргаар соль
- CLAUDE.md-д дүрэм нэм: «Татвар/НДШ/хууль хамааралтай ЯМАР Ч тоог кодод
  бичихийг хориглоно — `lib/regulatory`-оос огноотой lookup хийнэ.
  VAT/Payroll модуль хөгжүүлэхэд энэ ЗААВАЛ»
- AI туслахад: system prompt-д регулятор датаны хувилбар/огноог оруул
  (модель хуучирсан хувь таамаглахаас сэргийлнэ)

### Шат 4 — Feed-ийн суурь (зөвхөн бэлтгэл, сервер талыг ХИЙХГҮЙ)

- `meta.json`-д `snapshotVersion` (semver) + `publishedAt`
- `lib/regulatory/update.ts` — локал файлаас шинэ snapshot ачаалах,
  validate хийгээд солих функц (одоогоор гараар/script-ээр)
- Ирээдүйн зураглалыг файлын коммент дээр тэмдэглэ: гарын үсэгтэй
  (ed25519) remote snapshot татах → шалгах → унтраалттай солих;
  сүлжээгүй/төлбөргүй үед bundled snapshot-оор үргэлжлүүлнэ (систем
  хэзээ ч зогсохгүй, зөвхөн «дата хуучирсан байж магадгүй» анхааруулга)

## Хатуу дүрэм

- Lookup олдохгүй бол таамаглахгүй — алдаа шидээд UI/AI-д «энэ огнооны
  дата алга, шинэчлэлт хийнэ үү» гэж монголоор тайлбарлана
- Утга бүр `source` (хуулийн нэр/линк) заавал — эх сурвалжгүй дата орохгүй
- Энэ хавтас core-ийн кодоос import хийхгүй (нэг чиглэлтэй хамаарал:
  core → regulatory дата)

## Хамрахгүй

- Remote feed сервер, гарын үсэг, төлбөрийн шалгалт (launch-ийн дараа)
- VAT/Payroll модулиуд өөрсдөө (тусдаа том ажил — гэхдээ тэд энэ
  давхаргыг ашиглах ЁСТОЙ)
- Бусад улсын дата (бүтэц нь `regulatory/mn/` гэж улсаар салгагдсан нь
  ирээдүйд зориулсан орон зай, одоо зөвхөн mn)
