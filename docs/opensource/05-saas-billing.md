# Фаз 05 — SaaS багц + лимит (Billing)

> ⚠️ **Урьдач нөхцөл: Фаз 01 (multi-tenancy) бүрэн дууссан байх.**
> План байгууллагад уягдана — хэрэглэгчид биш.

## Зорилго

Cloud хувилбарт багцын (план) бүтэц, хэрэглээний хэмжилт, лимитийн
хэрэгжилт. Төлбөрийн интеграц (QPay) энэ фазад ХИЙХГҮЙ — эхэндээ гараар
нэхэмжлэх явуулж, admin-аар план идэвхжүүлнэ. Хэмжилт, лимит, план
солих механизм нь автомат байх ёстой.

## Багцын бүтэц (эхлэлийн — тоог амархан өөрчилдөг байх)

| Код | Нэр | Үнэ/сар | Хэрэглэгч | Компани | AI асуулт/сар |
|-----|-----|---------|-----------|---------|---------------|
| `free` | Гарааны | 0₮ | 1 | 1 | 20 |
| `standard` | Стандарт | 150,000₮ | 3 | 1 | 300 |
| `pro` | Про | 400,000₮ | 10 | 3 | 1000 |
| `firm` | Фирм | тохиролцоно | ∞ | клиент тутам | клиент тутам |

- План тодорхойлолт **DB хүснэгтэд** (`plans`), код нь зөвхөн ерөнхий
  enforcement — үнэ/лимит өөрчлөх нь дата өөрчлөлт байх ёстой
- Self-host build-д billing огт идэвхгүй: `BILLING_ENABLED` env flag,
  default `false`. Flag унтраалттай үед лимит шалгалт огт хийгдэхгүй —
  **нээлттэй кодоор бүрэн ажиллагаатай систем** (FSL-ийн амлалттай нийцнэ)

## Хийх ажил

### Шат 1 — Schema

```
plans           id, code, name, priceMnt, maxUsers, maxCompanies,
                aiQuestionsPerMonth, sortOrder, isActive
subscriptions   id, organizationId, planId, status(active|past_due|expired),
                periodStart, periodEnd, note
ai_usage        organizationId, month (YYYY-MM), questionCount
                unique(organizationId, month)
```

### Шат 2 — Enforcement

- `lib/billing/limits.ts` — `checkLimit(orgId, "aiQuestion" | "user" | "company")`
- AI chat route: асуулт бүрд counter += 1 (transaction-тай), лимит хүрвэл
  монголоор зөөлөн мэдэгдэл + план ахиулах линк. **Хатуу таслахгүй зүйл:**
  тайлан үзэх, бичилт хийх, экспорт — үндсэн нягтлан бодох ажиллагаа
  ЯМАР Ч планд хязгаарлагдахгүй (лимит зөвхөн AI, хэрэглэгчийн тоо,
  компанийн тоонд)
- Гишүүн урих үед maxUsers шалгана; компани нэмэхэд maxCompanies
- `past_due` → 14 хоногийн grace, дараа нь `expired`
- **`expired` = READ-ONLY, хэзээ ч дата устгахгүй.** Бүх юмаа харна,
  экспортолно, зөвхөн шинэ бичилт хийж чадахгүй. Энэ дүрэм ХАТУУ —
  нягтлангийн дата барьцаалах нь итгэлийг устгана

### Шат 3 — UI

- Тохиргоо → Багц хуудас: одоогийн план, хэрэглээ (AI асуулт х/300,
  хэрэглэгч 2/3), план солих хүсэлт (эхэндээ email/холбоо барих линк)
- Topbar-д лимит ойртсон үед (90%+) жижиг анхааруулга
- Admin (эзний) хэрэгсэл: план оноох энгийн script эсвэл хамгаалагдсан
  хуудас (эхэндээ script хангалттай)

## Хатуу дүрэм

- Дата устгах, барьцаалах ЯМАР Ч механизм байхгүй
- `BILLING_ENABLED=false` үед систем лимитгүй, төлбөрийн UI огт
  харагдахгүй — self-host хэрэглэгчид billing-ийн ул мөр үзэгдэхгүй
- Үнэ, лимит кодод hardcode хийхгүй — plans хүснэгтээс

## Хамрахгүй

- QPay/банк интеграц (дараагийн шат — эрэлт батлагдсаны дараа)
- Урамшуулал, купон, туршилтын хугацааны автоматжуулалт
- Partner (фирм) планы клиент-тутмын автомат тооцоо — эхэндээ гараар
