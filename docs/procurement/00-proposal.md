# Хангамжийн модуль (Procurement / PO + landed cost) — Дизайны санал v2

**Төлөв:** Product owner-ийн эцсийн батлалт хүлээж байна · **Огноо:** 2026-09-11
**v2 өөрчлөлт:** Product owner-ийн 8 шийдвэрийг тусгав — хүлээн авалтыг PO үнээр орлогодох, хоёр түр данс, Монголбанкны ханш суурь, PO хаалтын бичилт, сар хаалтын хориг.

---

## 1. Хураангуй

Өртгийн модуль (сарын жигнэсэн дундаж) олон эх сурвалжийн зардлыг **аль хэдийн** орлогдох өртөгт нийлүүлдэг (`receipt_capitalize` + `landed_cost` = Inbound → дундаж → зарлага/эцсийн үлдэгдэл) — энэ хэсэг **өөрчлөгдөхгүй**. Хангамжийн модуль нь худалдан авалтыг **нэг объект (PO)** болгож, эхний алхмуудыг автоматжуулж, хоёр түр дансаар хаалтыг хянана:

| Алхам | Одоо | v2 санал |
|---|---|---|
| PO | байхгүй | `purchase_orders` + `purchase_order_lines`; олон нэхэмжлэхтэй; нийлбэр таарч байж хаагдана; хаагдсан PO-д нэхэмжлэх нэмэгдэхгүй |
| Бараа хүлээн авах | АП нэхэмжлэх = орлого (тоо л, өртөг гараар) | **Хүлээн авалтын баримт** (нэхэмжлэхээс өмнө/дараа): `Dr Бараа / Cr Бараа материалын түр данс` — PO үнэ × хүлээн авсан өдрийн Монголбанкны ханш, **автомат** |
| Нийлүүлэгчийн нэхэмжлэх | Dr Клиринг / Cr Өглөг | `Dr Өглөгийн түр данс / Cr Өглөг` — нэхэмжлэхийн өдрийн Монголбанкны ханш |
| Гааль, тээвэр г.м. | тусдаа гар хуваарилалт, холбоосгүй | Мөрөнд бүрэлдэхүүн → `Dr Өглөгийн түр данс / Cr Өглөг`; хуваарилалт → `Dr Бараа / Cr Бараа материалын түр данс`; импортын НӨАТ → 13620000 (капиталжихгүй) |
| PO хаах | байхгүй | `Dr Бараа материалын түр данс / Cr Өглөгийн түр данс`, зөрүү → ханшийн ашиг/алдагдал; хоёр түр данс **0** |
| Төлбөр | одоогийн касс | Арилжааны банкны (гүйлгээний) ханш; зөрүү → ханшийн ашиг/алдагдал (одоогийн код) |
| Сар хаалт | ноорог үлдсэн бол хаагдахгүй | + тухайн сард хүлээн авалттай **нээлттэй PO** байвал хаагдахгүй |
| PWA | бэлэн | өөрчлөлтгүй |

Хэмжээ: **M–L (~15–18 ажлын өдөр)** — хүлээн авалтын баримт v1-д орсон тул v1-ээс 3–4 өдөр нэмэгдэв.

### 3.3 Урсгал (бүх бичилт Business Object = PO)

```
① PO үүсгэх (ноорог) → Батлах (open)                      GL бичилт ҮГҮЙ
② Бараа хүлээн авах — "Хүлээн авалт" баримт (PO панелиас; нэхэмжлэхээс өмнө ч, дараа ч; хэсэгчилсэн)
   огноо, агуулах, МБ ханш (автомат татна), мөр = PO мөрийн хүлээн аваагүй үлдэгдэл
   Батлах → орлогын хөдөлгөөн confirmed (sourceType='po_receipt', assertPeriodOpen)
          → АВТОМАТ receipt_capitalize: amount = qty × PO нэгж үнэ × хүлээн авсан өдрийн МБ ханш
            Dr Бараа / Cr Бараа материалын түр данс            ← бараа энэ ханшаар үнэлэгдэнэ (#4)
③ Нийлүүлэгчийн нэхэмжлэх — PO панелиас "Нэхэмжлэх үүсгэх" → АП панель prefill (нэхэмжлээгүй үлдэгдэл × PO үнэ, PO валют)
   ханш = нэхэмжлэхийн өдрийн МБ ханш (автомат, засаж болно)
   Батлах → Dr Өглөгийн түр данс / Cr Өглөг (MNT = валют дүн × ханш)
   Хөдөлгөөн ҮҮСГЭХГҮЙ (орлого ②-оос). Хаагдсан PO → [PO_CLOSED] алдаа
④ Нэмэлт зардлын нэхэмжлэх (гааль, тээвэр, брокер …) — PO панелиас; мөр бүрд бүрэлдэхүүн (cost_components)
   Батлах → Dr Өглөгийн түр данс / Cr Өглөг (бүрэлдэхүүнтэй мөр); импортын НӨАТ → Dr 13620000 (бүрэлдэхүүнгүй)
⑤ Хуваарилалт — "Хуваарилагдаагүй зардал" worklist; PO-гийн confirmed орлогууд урьдчилан сонгогдсон; суурь хэрэглэгч сонгоно
   → landed_cost: Dr Бараа / Cr Бараа материалын түр данс
⑥ PO хаах (нөхцөл: Σ хүлээн авсан = захиалсан; Σ нэхэмжилсэн (PO валют) = PO дүн мөр бүрээр; бүх зардал хуваарилагдсан)
   → Dr Бараа материалын түр данс (Σ Cr үлдэгдэл) / Cr Өглөгийн түр данс (Σ Dr үлдэгдэл)
   → зөрүү (ханшийн огнооны ялгаа) → Dr Ханшийн алдагдал / Cr Ханшийн ашиг     ← хоёр түр данс 0
   → status closed; цаашид нэхэмжлэх/хүлээн авалт нэмэгдэхгүй
⑦ Төлбөр — одоогийн касс: арилжааны банкны ханш, зөрүү → ханшийн ашиг/алдагдал (cash.ts:625-639 бэлэн)
⑧ Сар хаалт — runPeriodicCosting ӨӨРЧЛӨЛТГҮЙ; closePeriod: тухайн сард хүлээн авалттай нээлттэй PO байвал ХОРИГЛОНО (#7)
```

**PO-гүй худалдан авалт** (дотоодын жижиг): одоогийн зам хэвээр — АП бараатай мөр → орлого → нэхэмжлэхийн дүнгээр автомат капитализаци (#5).

### 3.4 Нийлбэр таарах хяналт (#1)

- PO мөр бүрд: `Σ нэхэмжилсэн тоо = захиалсан тоо` ба `Σ нэхэмжилсэн дүн (PO валют) = PO мөрийн дүн` — зөрвөл PO хаагдахгүй, юу зөрснийг PO панель улаанаар харуулна.
- Нийлүүлэгчийн нэхэмжлэх PO үнээс зөрвөл: нээлттэй PO-гийн мөрийн үнэ/тоог **засаж** тааруулна (аль хэдийн хүлээн авсан мөрийн үнийг өөрчилбөл дараагийн хүлээн авалтад л нөлөөлнө; өмнөх капитализаци хөндөгдөхгүй — зөрүү PO хаалтад ханшийн зөрүүтэй адил тусдаа мөрөөр гарна) — эсвэл нэхэмжлэхийг залруулна.
- Илүү нэхэмжлэх/илүү хүлээн авалт → `[OVER_INVOICED]` / `[OVER_RECEIVED]` алдаа.

### 3.5 Ханш (#4)

- Суурь ханш = **Монголбанкны албан ханш** тухайн өдрөөр (`lib/cash/exchange-rates.ts` mongolbank/official — бэлэн; огноогоор автоматаар татаж, баримтад хадгална, хэрэглэгч засаж болно).
- Хүлээн авалт: хүлээн авсан өдрийн ханш → **барааны өртөг**. Нэхэмжлэх: нэхэмжлэхийн өдрийн ханш → өглөг. PO хаалт: түр дансдын зөрүү (ханшийн огнооны ялгаа) → бодит ханшийн ашиг/алдагдал. Төлбөр: арилжааны банкны ханш → одоогийн касс логик.
- MNT нэхэмжлэх (гааль, дотоодын тээвэр): ханш 1 — зөрүү үүсэхгүй.

### 3.6 Хуваарилалт

- **PO мөр = бараа × тоо хэмжээ × нэгж үнэ = нийт үнэ** (PO валют). Үндсэн барааны **нэгж үнэ** нь орлогдох нэгж өртгийн суурь (× хүлээн авсан өдрийн МБ ханш).
- Нэмэлт зардал (гааль, тээвэр …) бүрд хэрэглэгч гурван аргын нэгийг сонгоно (одоогийн `lib/costing/allocation.ts` хөдөлгөгч, `allocate({base})`):
  - **Нийт үнийн дүнгээр** — жин = PO мөрийн нийт үнэ (тоо × PO нэгж үнэ, хүлээн авалтын MNT дүн); өмнө хуваарилсан зардал жинд ОРОХГҮЙ (D6 = (а))
  - **Тоо хэмжээгээр** — жин = хүлээн авсан тоо
  - **Гараар** — бараа бүрд дүнг өөрөө бичнэ; Σ = зардлын дүн байх ёстой (одоогийн шалгалт), зөрвөл хадгалахгүй
- Зөвхөн хэрэглэгч (эсвэл AI tool ил `allocationBase` параметртэй) "Хуваарилах" дарсан үед; суурь урьдчилан сонгогдохгүй (OD-017).
- Зорилт = тухайн PO-гийн confirmed орлогууд (✓ урьдчилан); нэхэмжлэх орлогоос өмнө ирвэл "Хуваарилалт хүлээж байна" — орлого батлагдмагц PO панель сануулна.
- Хэсэгчилсэн орлого: нэг мөрөөс олон хуваарилалт, Σ ≤ мөрийн MNT дүн; PO хаалт бүх зардал хуваарилагдтал хүлээнэ.

### 3.6a Нийлүүлэгч ба хавсралт (2026-09-11 нэмэлт шаардлага)

- **Нийлүүлэгч** = `counterparties`-ийн `supplier` эсвэл `both` төрөлтэй харилцагч (АП-тай ИЖИЛ сонгогч — `CounterpartyPicker` reuse). PO панелийн толгойд нийлүүлэгчийн карт: нэр, ТТД, утас/имэйл, хаяг, банкны данс, төлбөрийн нөхцөл (харилцагчийн бүртгэлээс уншина; PO-д дахин хадгалахгүй), тухайн нийлүүлэгчийн нээлттэй өглөгийн үлдэгдэл, өмнөх PO-ууд.
- **Хавсралт** — шинэ нийтлэг хүснэгт `document_attachments` (entityType `purchase_order` — дараа АР/АП, касс зэрэгт ч ашиглагдана): `id, organizationId, entityType, entityId, kind, name, mediaType, sizeBytes, data (base64 — ai_attachments/компанийн лого-той ИЖИЛ хадгалалт), uploadedBy, createdAt`. Файл ≤ 8MB (eBarimt route-тай ижил хязгаар), PDF/зураг/Excel/Word.
- Хавсралтын **төрөл** (`kind`, UI шошго): үнийн санал (quotation), проформа (proforma), гэрээ (contract), нэхэмжлэх (invoice), савлагааны жагсаалт (packing_list), тээврийн баримт (bill_of_lading), гаалийн мэдүүлэг (customs_declaration), гарал үүслийн гэрчилгээ (certificate), бусад (other). Жагсаалт кодод хаалттай биш — `kind` text, UI-д зөвлөх шошго.
- PO панелийн "Хавсралт" таб: жагсаалт (төрөл, нэр, хэмжээ, огноо, хэн), нээх/татах (`/api/attachments/<id>` — org шалгалттай), устгах (нээлттэй PO-д л). Хаагдсан PO-д хавсралт нэмж болно (аудит), устгахгүй.
- Нэхэмжлэх хавсралтаас АП ноорог үүсгэх — одоогийн eBarimt OCR route-ыг PO context-тэй (purchaseOrderId prefill) дуудна (v1-д товч; OCR логик өөрчлөгдөхгүй).

## 4. Тоон жишээ v2 (ханшийн зөрүүтэй)
