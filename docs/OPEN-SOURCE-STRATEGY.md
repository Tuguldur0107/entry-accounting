# Entry — Open Source стратеги

*Ноорог v0.1 · 2026-08-07 · Хэлэлцэх зорилготой*

---

## 0. Эхлээд нэг зөрчлийг шулуухан хэлье

Чиний сонгосон гурван зүйл хоорондоо зөрчилдөж байна:

| Сонголт | Утга |
|---------|------|
| «Бүгд нээлттэй» | OSI-ийн жинхэнэ open source (MIT/Apache/GPL) |
| «Аудит/нягтлан фирмүүд self-host хийнэ» | Тэд ОЛОН клиентэд үйлчилнэ |
| «Дамжуулан худалдахаас сэргийлмээр байна» | Дахин зарахыг хориглох |

**OSI лиценз нь дахин зарах ЭРХИЙГ баталгаажуулдаг.** MIT/Apache/AGPL аль нь ч
"чи үүнийг зарж болохгүй" гэж хэлж чадахгүй — тэгвэл тэр нь тодорхойлолтоороо
open source биш болно. AGPL ч гэсэн зөвхөн *эх кодоо нээ* гэж шаарддаг болохоос
*битгий зар* гэж хэлдэггүй.

Тиймээс сонголт хоёр:

**A. Жинхэнэ open source (Apache-2.0)** — хэн ч, юу ч хийж болно. Хамгаалалт нь
зөвхөн брэнд + хостинг + сургалт + өгөгдлийн feed. Хамгийн хурдан тархах, гэхдээ
аудит фирм чиний системийг "XYZ Accounting" нэрээр клиентдээ зарахыг хууль ёсны
болгоно.

**B. Source-available (FSL) — ЗӨВЛӨЖ БАЙНА.** Repo нь GitHub дээр нээлттэй, хэн ч
уншиж, fork хийж, өөрчилж, өөрийн компанидаа үнэгүй ашиглана. ЗӨВХӨН "гуравдагч
этгээдэд үйлчилгээ болгон санал болгох" нь хориотой — тэр тохиолдолд Partner
лиценз авна. Хэрэглэгчийн 95%-д энэ нь open source-оос ялгагдахгүй мэдрэгдэнэ.

Доорх бүх төлөвлөгөө **B** дээр суурилсан.

## 1. Лицензийн бүтэц

### Үндсэн лиценз: FSL-1.1-Apache-2.0

[Functional Source License](https://fsl.software) — Sentry-ийн зохиосон, одоо
хамгийн нэр хүндтэй "fair source" лиценз.

```
Зөвшөөрөгдөх:  унших, fork, өөрчлөх, дотооддоо ашиглах, дахин тараах
Хориотой:      Competing Use — өөрөөр хэлбэл Entry-г (эсвэл түүнтэй ижил
               төстэй бүтээгдэхүүнийг) гуравдагч этгээдэд төлбөртэй
               үйлчилгээ/бүтээгдэхүүн болгон санал болгох
Автомат:       2 жилийн дараа хувилбар бүр Apache-2.0 болж бүрэн чөлөөлөгдөнө
```

Сүүлийн мөр чухал: **энэ нь community-ийн итгэлийг хадгална.** "Хэзээ ч чөлөөлөхгүй"
гэсэн лицензүүд (BUSL-ийн зарим хувилбар) developer-үүдийг хөөж явуулдаг.

### Аудит фирмийн саарал бүс — тодорхой заавал бичих

FSL "internal business purposes"-ыг зөвшөөрдөг. Гэтэл аудит фирм клиентийнхээ
бүртгэлийг Entry дээр хөтөлж байгаа нь дотоод хэрэглээ үү, эсвэл үйлчилгээ үү?
Энийг маргаанд үлдээж болохгүй. `LICENSE-FAQ.md`-д ингэж бичнэ:

| Тохиолдол | Лиценз |
|-----------|--------|
| Компани өөрийн бүртгэлдээ ашиглана (хэдэн салбартай ч) | **Үнэгүй** |
| Нягтлан фирм клиентийн дата оруулна, **клиент нэвтрэх эрхгүй** | **Үнэгүй** |
| Клиент өөрөө нэвтэрч ашиглана / клиентэд төлбөртэй хандалт өгнө | **Partner лиценз** |
| Entry-г өөр нэрээр брэндлэн зарна | **Partner лиценз + брэндийн зөвшөөрөл** |

Энэ шугам нь **хянахад амархан**: клиент login-той юу, үгүй юу. Эрсдэлийг орлогын
суваг болгож хувиргаж байна — хориглохын оронд үнэлж байна.

### Дагалдах эрх зүйн 2 зүйл

1. **CLA (Contributor License Agreement).** Гадны хүн pull request илгээхэд
   copyright-ыг чамд шилжүүлэх/өргөн лиценз өгөх. [CLA Assistant](https://cla-assistant.io)
   GitHub-д үнэгүй автоматжуулна. Үүнгүйгээр чи хожим лицензээ өөрчилж,
   commercial лиценз зарж чадахгүй болно. **Эхний PR ирэхээс өмнө хийх.**

2. **Барааны тэмдэг.** "Entry" үг + лого-г Оюуны өмчийн газарт бүртгүүл. Үнэ бага
   (хэдэн зуун мянган ₮), гэхдээ Монголд бодитоор хэрэгжих ЦОРЫН ГАНЦ хууль
   зүйн хөшүүрэг. 2 жилийн дараа код Apache болсон ч **нэрийг чинь хэн ч
   ашиглаж чадахгүй.** WordPress, Redis, Firefox бүгд ингэж хамгаалдаг.

## 2. Хамгаалалтын 5 давхарга

Лиценз бол 5 давхаргын нэг нь л. Монголд шүүхээр хэрэгжүүлэх нь удаан, үнэтэй тул
**практик давхаргууд илүү чухал.**

### ⛔ Эхлээд: "цаг ажиллаж файл устдаг" санааг бүү хий

| Шалтгаан | Тайлбар |
|----------|---------|
| Ажиллахгүй | Код нээлттэй → нэг commit-оор устгагдана. 10 минутын ажил |
| Итгэлийг устгана | Нягтлан бодогч гэдэг хамгийн болгоомжтой хэрэглэгч. "Энэ програм миний датаг устгаж болно" гэдэг мэдээлэл тархвал SaaS чинь ч үхнэ |
| Хууль зүйн эрсдэл | Татварын шалгалтын дундуур дата уствал хохирлыг ЧИ хариуцна |
| Урвуу нөлөө | Хамгийн шударга хэрэглэгч л гэмтэнэ; хулгайч аль хэдийн patch хийсэн байна |

Оронд нь: **зогсоох биш, хоцроох.**

### Давхарга 1 — Зохицуулалтын feed (хамгийн хүчтэй)

Татварын хувь, НДШ хязгаар, ХАОАТ bracket, eBarimt схем, e-tax формат — **эдгээр
жил бүр өөрчлөгддөг.** Код 100% нээлттэй байсан ч энэ өгөгдөл шинэчлэгдэхгүй бол
систем 6 сарын дотор ашиггүй болно.

```
entry-regulatory-mn/   → GitHub дээр нээлттэй (community засаж болно)
api.entry.mn/regulatory → гарын үсэгтэй (signed) feed
   Үнэгүй tier:  6 сар хоцорсон жилийн snapshot
   Төлбөртэй:    шууд, хуулийн өөрчлөлт гармагц
```

Fork хийсэн хүн кодыг авч чадна, гэхдээ **хууль зүйн ажиллагааг** авч чадахгүй.
Энэ нь ёс зүйн хувьд цэвэр, техникийн хувьд эвдэгдэхгүй, сэргээгдэх moat.

### Давхарга 2 — AI/MCP gateway

AI туслах ажиллахад Anthropic/OpenAI түлхүүр хэрэгтэй. Хэрэглэгчид өөрсдийн
түлхүүрээ хийж болно (нээлттэй байх ёстой), **эсвэл** чиний gateway-гээр дамжуулж
болно — тэгвэл setup хялбар, дата Монголд үлдэнэ, чамд ашиглалтын харагдац
өгнө. Ихэнх нь хоёр дахийг сонгоно. Хориглох биш, хялбар болгох замаар барих.

### Давхарга 3 — Брэнд + Partner бүртгэл

Монголын нягтлан бодох салбар жижиг. `entry.mn/partners` дээр албан ёсны
партнёрын жагсаалт нийтэл. Тэндгүй компаниас үйлчилгээ авахгүй байхыг зах зээл
өөрөө зохицуулна. Нэр хүнд нь торгуулиас илүү үр дүнтэй.

### Давхарга 4 — Marketplace бүртгэл

Skill, тайлан, дансны загвар нийтлэхэд Entry аккаунт шаардлагатай. Fork хийсэн
хүн ecosystem-ээс тасарна. Цаг хугацаа өнгөрөх тусам ecosystem нь код өөрөө
өөрөөсөө үнэтэй болно.

### Давхарга 5 — Сургалт + сертификат

Кодыг хуулж болно, мэдлэгийг хуулж болохгүй. Хамгийн ашигтай, хамгийн
хамгаалагдсан бүтээгдэхүүн энэ.

## 4. ⚠️ Нээхээс ӨМНӨ заасал засах: multi-tenancy

Repo-г шалгалаа (шинэчилсэн 2026-08-08 — аудит + НӨАТ/Цалин/Audit log
нэмэгдсэний дараа):

```
lib/db/schema.ts    2,006 мөр, 55 хүснэгт
userId лавлагаа     105 (schema-д), 1,240 (lib/ бүхэлдээ)
organizationId      0
```

`CLAUDE.md` дээр «нэг хэрэглэгч = нэг компани» гэж бичсэн. **Аудит фирмүүд
чиний зорилтот self-host хэрэглэгч бол энэ загвар шууд бүтэхгүй.** Нэг нягтлан
30 клиенттэй бол 30 өөр аккаунт руу нэвтрэх үү?

Хэрэгтэй өөрчлөлт:

```
organizations        (компани — нэр, ТТД, валют, тохиргоо)
memberships          (user × organization × role)
49 хүснэгт:          userId → organizationId  [migration]
runAsUser()          → runAsOrg()  (lib/auth.ts, AsyncLocalStorage)
MCP token            → organization-scoped
```

**Энийг ЗААВАЛ нээхээсээ өмнө хий.** Гадны fork үүссэний дараа өгөгдлийн загвар
өөрчлөх нь community-г хоёр хуваана — бүх custom код эвдэрнэ, чиний сургалтын
материал хүчингүй болно. Ойролцоогоор 2–4 долоо хоногийн ажил, одоо хийвэл хямд.

## 5. Customize хийх архитектур (техникийн гол ажил)

Хэрэглэгч core файлыг засвал `git pull` хийх бүрдээ conflict гарна → сургалт
утгагүй болно → marketplace боломжгүй болно. Тиймээс **өргөтгөлийн цэг**
хэрэгтэй.

```
custom/                         ← Upstream ЭНД ХЭЗЭЭ Ч БИЧИХГҮЙ
├── entry-package.json          манифест: нэр, хувилбар, нийцтэй core хүрээ
├── accounts/                   Салбарын дансны сан (барилга, худалдаа, уул уурхай)
├── posting-rules/              Posting template — КОД БИШ ДАТА (JSON)
├── reports/                    report_line_mappings өргөтгөл + custom тайлан
├── tools/*.ts                  AI/MCP tool → lib/ai/tools.ts руу авто-бүртгэнэ
├── skills/                     .claude/skills — нягтлан бодох skill-үүд
├── columns/                    lib/grid/columnTypes.ts custom бүртгэл
├── theme.css                   ui-kit/tokens.css override
└── hooks/                      beforePost / afterPost / beforeClose / onPeriodClose
```

**Хатуу дүрэм 2:**

1. Хэрэглэгч `custom/`-оос ГАДНА юу ч засахгүй
2. Core `custom/`-д хэзээ ч бичихгүй

Энэ хоёр биелвэл: `git pull` үргэлж ажиллана · сургалт заах боломжтой болно ·
marketplace-ийн бараа гэдэг нь зүгээр л `custom/` багц болно · дэмжлэг үзүүлэхэд
"custom/ хавтсаа илгээ" гэхэд хангалттай.

Одоо байгаа код энэ рүү аль хэдийн хагас явж байна — `costing_account_settings`,
`costing_item_settings`, `report_line_mappings`, `segment_configs`,
`inventory_issue_types` бүгд дата-driven. Тэр зарчмаа гүйцээх хэрэгтэй:
**posting template-үүдийг кодоос дата руу гарга.**

### Marketplace-ийн нэгж = `entry-package.json`

```json
{
  "name": "barilga-coa",
  "version": "1.2.0",
  "title": "Барилгын салбарын дансны сан",
  "author": "…",
  "entryCompat": ">=2.0.0 <3.0.0",
  "license": "commercial",
  "price": 250000,
  "provides": ["accounts", "posting-rules", "reports"]
}
```

Багц = хавтас + манифест. Суулгах = `npx entry add barilga-coa`. Хялбар байх нь
чухал.

## 6. Сургалт — 2 track + сертификатын flywheel

### Track A · Хэрэглэгч (нягтлан бодогч) — 2 өдөр

Систем ашиглах, AI туслахтай ажиллах, Excel импорт, сар хаалт, тайлан унших,
`reconcile_modules`-аар тулгалт хийх.

### Track B · Builder (IT engineer / CEO / ахлах нягтлан) — 3 өдөр

| Өдөр | Агуулга |
|------|---------|
| 1 | Архитектур танилцуулга. `CLAUDE.md` гэж юу вэ, яагаад энэ нь заавар вэ. Claude Code суулгах, repo-г уншуулах |
| 2 | `custom/` дотор ажиллах: дансны сан, posting rule, тайлан нэмэх. Claude Code-той хос программчлал. Git workflow, upstream-ээс merge хийх |
| 3 | Skill бичих, MCP tool нэмэх, deploy, backup, эрхийн тохиргоо. Гэрийн даалгавар: өөрийн компанийн нэг бодит хэрэгцээг хэрэгжүүлэх |

### Flywheel

```
Сургалт → Сертификат → Partner бүртгэлд орох эрх → Marketplace-д
нийтлэх эрх → Экосистем өснө → Entry илүү үнэтэй болно → Сургалтын
эрэлт өснө
```

`CLAUDE.md` файл чинь аль хэдийн маш сайн сургалтын материал болсон байна —
Track B-ийн үндсэн сурах бичиг нь тэр.

үүрэг гүйцэтгэнэ.

## 10. Гурван эрсдэл

**1. Дэмжлэгийн ачаалал.** Open source болмогц асуулт үерлэнэ. GitHub Discussions
дээр л хариул, хувийн чатаар бүү хариул — нэг хариулт олон хүнд үйлчилнэ.
Үнэгүй дэмжлэгийн хил хязгаарыг эхнээс нь бич.

**2. Фокус тарах.** Холимог загвар (SaaS + сургалт) сонгосон нь зөв, гэхдээ энэ
хоёр өөр өөр бүтээгдэхүүн, өөр өөр борлуулалт. Эхний 6 сард **SaaS = үндсэн,
сургалт = хоёрдогч** гэж тодорхой шийдэж, дараа нь тоо баримтаар дахин шийд.

**3. Хэт эрт нээх.** Multi-tenancy засахаас өмнө нээвэл дараа нь засах өртөг
10 дахин нэмэгдэнэ. 4 долоо хоног хүлээх нь зөв.
