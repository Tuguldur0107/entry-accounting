## eBarimt 3.0 — товч

Дэлгэрэнгүй: `03-ebarimt-integration-plan.md` (дизайн), `docs/deployment/ebarimt.md`
(нэвтрүүлэлт). Гол зарчим:

- PosAPI 3.0 нь **мерчантын талын үйлчилгээ** — Entry HTTP-ээр дууддаг.
  `server` горим (Railway-ийн `posapi` service, зөвлөж буй) эсвэл `browser`
  горим (кассын PC-ийн localhost, кассын дэлгэц өөрөө илгээнэ)
- Борлуулалт батлагдмагц `pos_ebarimt_submissions` дараалалд орж **async**
  илгээгдэнэ — борлуулалт ХЭЗЭЭ Ч хүлээхгүй, илгээлтээс болж зогсохгүй
- ДДТД / сугалаа / QR ирмэгц баримтад гарна; амжилтгүй бол backoff + 3
  дараалсан алдаанд мэдэгдэл; зассаны дараа гараар [Дахин илгээх]
- Буцаалт → эх ДДТД цуцлагдаж, үлдсэн мөрөөр шинэ баримт
- **Код ЗОХИОХГҮЙ:** барааны ангилал (7 орон), татварын бүтээгдэхүүний код
  (3 орон), төлбөрийн хэлбэрийн eBarimt код дутвал баримт илгээгдэхгүй,
  шалтгаан нь UI-д ил (`[EBARIMT_*]`)
- **Борлуулалт бүрд eBarimt-гүй явуулах:** төлбөрийн диалогийн «eBarimt баримт
  илгээх» switch (default асаалттай; унтраавал худалдан авагчийн блок нуугдана)
  → `pos_sales.ebarimtStatus = "skipped"`, дараалалд орохгүй, жагсаалтад
  «eBarimt илгээгээгүй» chip, панелиас [eBarimt илгээх]-ээр дараа илгээнэ;
  AI `create_pos_sale.skipEbarimt`. Хуулийн үүрэг кассчны хариуцлагад — аудитын
  хураангуйд ил
- **Бэлэн байдлын шалгалт (`lib/ebarimt/readiness.ts`, ЦЭВЭР+тесттэй):** дээрх
  дутууг switch АСААХААС ӨМНӨ тоолж нэрлэнэ (бүлгээс өвлөсөн код тооцогдоно) —
  UI-д блок + server талд `updatePosSettings` хориг + `get_ebarimt_status`
- **v2 (2026-09-20, албан баримттай тулгасан):** операторын төвлөрсөн PosAPI
  (нэг суулгац, олон мерчант); **сугалаа/QR ХАДГАЛАГДАХГҮЙ** — борлуулалтын мөчид
  ≤8 сек хүлээж нэг удаа хэвлэнэ, дахин хэвлэхэд ДДТД; **хэсэгчилсэн буцаалт
  `inactiveId` гинжээр** (сугалаа дахин олгохгүй), бүтэн буцаалт DELETE;
  `/rest/info`-оос сугалааны нөөц / ТЕГ рүү илгээлтийн хоцролт / PosAPI хүрэлцээ
  → самбар + мэдэгдэл; татварын кодын албан лавлах (3 орон) сонгогч

## Мэдэгдэж буй хязгаарлалт

- Төлбөрийн диалог Төлсөн/Үлдэгдэл/Хариултыг локал бодно — эцсийн шалгалт server `planPayments`
  (`[APPROVAL_REQUIRED]`, `[NEGATIVE_STOCK]`, `[CREDIT_LIMIT]` алдаа тэр чигээрээ харагдана).
- Борлуулалтын жагсаалтад баримт бүрийн COGS багана байхгүй (мөр бүрийнх панельд, нэгтгэл тайланд).
- Ханшийн бэлэн төлбөр (валютын бэлэн) ээлж нээхэд гараар өгсөн ханшаар — Монголбанкны ханш татахгүй
  (арилжааны бэлэн мөнгөний ханш нь албан ханш биш, §5b дүрэм).
- eBarimt: хотын татвар (НХАТ) хараахан дэмжигдээгүй (`totalCityTax` үргэлж 0) —
  зочид буудал/ресторан/барын харилцагчид шаардлагатай бол тусдаа change-control.
- eBarimt: зээлээр (credit) борлуулалт ч RECEIPT-ээр илгээгдэнэ (INVOICE төрөл
  хараахан хэрэглэгдээгүй) — ТЕГ-ийн зөвлөмжийг мерчант багцаас тулгах (§8 T3).
- eBarimt: ТЕГ-ийн ангилалын кодын бүрэн лавлах татагддаггүй — хэрэглэгч кодоо
  гараар / Excel-ээр оруулна (код ЗОХИОХГҮЙ).
